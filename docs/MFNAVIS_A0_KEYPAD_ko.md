# MFNavis_A0 입력 배치

시작 시 AW9523B 감지로 결정된 `board_mode=MFNavis_A0`일 때만 이 배치를
사용한다. 기존 보드는 기존 키 매핑·설정을 그대로 사용하며 별도 설치 옵션이나
패키지는 필요 없다. 소스 업데이트 후 앱을 다시 시작하면 적용된다.

| 스위치 | 기본 입력 |
| --- | --- |
| SW1 | 상 8 / 하 2 / 좌 4 / 우 6 / 중앙 5 |
| SW2 | 상·하·좌·우 방향키 / 중앙 예약 |
| SW3 | 0 |
| SW4 | F3 (예약) |
| SW5 | F2 (예약) |
| SW6 | F1 (예약) |
| SW7 | 사각 키 |
| SW8 | − |
| SW9 | + |
| SW10 | A (예약) |

예약 키도 눌림·해제 이벤트가 발생하지만 기본 앱 기능은 지정하지 않았다.
특히 SW2 중앙을 Enter로 처리하거나 SW10을 기존 문자 A 기능으로 연결하지 않는다.
설정의 Keyboard → Test Keys에서 예약 키를 포함한 모든 입력을 확인할 수 있다.
SW2 왼쪽으로 검사·키 지정 화면을 빠져나온다.

입력 식별자는 `A0_SW1_UP`, `A0_SW2_CENTER`, `A0_SW4`처럼 USB 키보드와
분리했다. 따라서 기존 USB A/F 키 할당이 A0 예약 키에 적용되지 않는다.
기존 Keyboard 기능 할당 화면에서 예약 키를 할당할 수 있으며 `keyboard_mapping`에
저장된다. 현재 제공되는 마운트 관련 기능 목록은 유지했고, 추후 기본 기능/할당
기능을 확장할 수 있도록 물리 배치와 기본 동작을 `keypad_a0.py`에 분리했다.
메뉴 조작에 필요한 SW2 방향키와 SW7은 재할당 대상에서 제외한다.

숫자는 눌림·해제를 각각 전달하여 기존 숫자 입력 및 마운트 누르는 동안 이동을
지원한다. 방향 상·하는 1초 이후 반복하고, 좌·우·사각의 길게 누르기도 지원한다.
사각을 누른 상태로 방향키·0·+/−를 누르면 기존 사각 조합 동작을 사용한다.
입력은 25ms 이상 안정된 뒤 처리하며 미사용 접점은 무시한다.

## 배선

ROW0..4 = BCM GPIO19, 17, 18, 22, 20.
COL0..3 = BCM GPIO16, 23, 26, 27.

2026-10-30 실제 장착 상태에서 상·하·좌·우·중앙을 순서대로 눌러 확인한
조이스틱 방향은 **D=상, C=좌, E=우, A=중앙, B=하**다.
SW1 COM은 COL0, SW2 COM은 COL1에 연결된다.

| 행 | SW1/COL0 | SW2/COL1 | COL2 | COL3 |
| --- | --- | --- | --- | --- |
| ROW0 (B) | 2 | 하 | SW3: 0 | SW8: − |
| ROW1 (E) | 6 | 우 | SW4: F3 | SW9: + |
| ROW2 (C) | 4 | 좌 | SW5: F2 | SW10: A |
| ROW3 (A) | 5 | 중앙 예약 | SW6: F1 | 미사용 |
| ROW4 (D) | 8 | 상 | SW7: 사각 | 미사용 |

## 단독 실물 검사

앱과 GPIO를 동시에 열지 않도록 서비스를 중지하고 아래 도구를 실행한다.
각 입력의 이름, Linux 코드, A0 식별자, 눌림·해제, 기본 앱 키코드를 JSON으로
출력하며 앱이나 마운트로 전달하지 않는다. 끝나면 서비스를 다시 시작한다.

```bash
cd ~/MFNavis
sudo systemctl stop mfnavis.service
PYTHONPATH=python .venv-trixie/bin/python python/scripts/test_a0_keypad.py --seconds 60
sudo systemctl start mfnavis.service
```

두 조이스틱을 각각 상·하·좌·우·중앙 순서로 누른 뒤 SW3부터 SW10까지 누른다.
사각 조합과 길게 누르기는 별도로 확인한다. 자동 테스트는
`python/tests/test_keypad_a0.py`에 있다.

## 실물 검증 (2026-10-30)

SW1·SW2 각 5개와 SW3~SW10의 총 18개 접점에서 눌림 18회·해제 18회를
확인했다. 초기 접점 설명과 실제 장착 방향이 반대여서 상하·좌우 매핑을
실측에 맞춰 수정했다. 수정 후 두 조이스틱을 각각 상·하·좌·우·중앙 순서로
다시 눌러 총 10회 눌림·10회 해제와 정확한 방향을 확인했다.
예약 키 5개도 고유 식별자로 인식했고 기본 앱 키코드는 발생하지 않았다.

관련 자동 테스트 111개 및 Nox lint/format 검사가 통과했다. 실물에서 확인한
범위는 단독 눌림·해제이며, 길게 누르기·사각 조합·사용자 할당은 자동 테스트로
검증했다. 원본 이벤트와 집계는 장비의
`~/MFNavis_data/test_data/keypad-a0-20261030/`에 저장했다.
