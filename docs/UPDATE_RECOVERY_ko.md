# 코드 업데이트 준비와 복원

`pifinder_update.sh`는 설치된 브랜치를 유지하며 fast-forward 후보만 사용한다. 운영 서비스 재시작, 부팅 설정 변경, 시스템 패키지 설치와 OS 마이그레이션은 수행하지 않는다.

1. 로컬 추적 파일 변경, 분리된 HEAD, Cedar 산출물, 초기화되지 않은 MF 서브모듈을 검사한다.
2. 요구 패키지 목록, OS 마이그레이션, `pi_config_files`, 서브모듈 구조 변경이 있으면 **반영 전에 중단**한다. 이런 릴리즈는 별도 설치 환경에서 준비·검증해야 한다. 이 코드 업데이트 기능이 시스템 설치까지 자동으로 처리한다고 간주하면 안 된다.
3. `.git/update-transaction/candidate`에 후보를 복제하여 고정된 MF 커밋을 빌드·시험하고 현재 Python 환경의 `pip check`를 실행한다. 디스크 공간과 네트워크가 필요하지만 시스템 Python에 패키지를 설치하지 않는다.
4. 기존 MF 빌드와 Git 커밋을 보관한 후 소스·서브모듈·준비된 빌드를 반영한다. 일반적인 실패 시 기존 소스와 MF 빌드를 복원한다. 복원 자체가 실패하면 복원 자료를 남긴다.

이는 파일 시스템 전체의 원자적 전환이나 실행 중 프로세스의 자동 전환은 아니다. 업데이트 도중 전원 차단/SIGKILL은 자동 복원이 실행될 수 없다. 다음 업데이트를 차단하는 기록을 남기며, 부팅 경로는 수정하지 않는다. 이런 경우 서비스를 시작하기 전에 아래처럼 설치 경로를 지정해 복원한다.

```sh
python3 /설치경로/scripts/transactional_update.py /설치경로 --recover
```

복원은 기록된 이전/후보 커밋과 동일 브랜치에서만 허용한다. 이후 별도 편집이나 커밋이 있으면 수동 확인을 요구한다. 준비 중 중단되어 `journal.json`이 없다면 설치본은 아직 변경되지 않은 단계이며, 후보 디렉터리를 확인한 뒤 별도로 정리해야 한다.

`pifinder_post_update.sh`를 직접 실행하는 기존 설치 경로에는 시스템 패키지·OS 마이그레이션이 남아 있다. 이것은 코드 업데이트의 복원 범위 밖이다. 이번 작업에서는 실제 설치 갱신과 운영 서비스 변경을 실행하지 않는다.
