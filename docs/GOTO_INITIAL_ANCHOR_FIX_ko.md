# GoTo 시작 시 광학 좌표 대기 복구 — 2026-09-15

사용자가 다른 별자리 GoTo에서 마운트가 움직이지 않는 현상을 보고했다.
22:20:28/38/49의 요청은 `PiFinder GoTo requires a recent plate solve`로
차단됐다. 마운트는 연결·비주차·정지 상태였고 이후 전처리 솔빙도 성공했지만,
기존 `pifinder_goto_blocked` 상태는 재검사하지 않아 요청이 계속 멈춰 있었다.

## 작업 전 계획

광학 좌표의 품질·출처·신선도 기준은 유지한다. 첫 요청이 광학 앵커 부족으로
막히면 최대 12초만 기다리고, 같은 검사에 통과한 좌표 스냅샷으로 Sync+GoTo를
이어간다. 시간 초과 후에는 새 요청이 필요하며 뒤늦게 자동 이동하지 않는다.
취소·목표 변경·GoTo 방식 변경·정렬·주차·외부 이동이 대기 요청을 취소하는지
회귀 검사한다. 이전 추적 목표로의 보정은 대기 중 해제한다.

메인에서 수정·검증·푸시 후 운영 서비스에 반영한다. 이전에 차단된 오래된 요청은
자동 재전송하지 않는다. 원본 상태·좌표·로그는 로컬 `work/goto_not_moving`에 보존한다.

## 검증 결과

GoTo·좌표·마운트·정렬 검사 216개 통과, 2개 skip. 변경 파일 lint/format과
GoTo 서비스 MyPy 검사도 통과했다. IMU·오래된/미래 시각의 광학 좌표는
이동 근거로 허용하지 않았다. 만료 시각에 도착한 광학 좌표도 재개하지 않으며,
취소·새 목표·GoTo 방식 변경·주차·외부 이동 회귀 검사를 포함했다.

현재 장비의 15초 좌표 전환을 읽기 전용으로 기록해 수정 서비스에 재생했다.
IMU 상태에서 요청하면 대기했고, 6.28초 뒤 실제 `solve`/high 좌표가 들어오자
모의 큐에 Sync+GoTo를 한 번만 발행했다. 실제 마운트 명령은 0회였다.

사용자 요청에 따라 이 수정부터 원격 푸시는 보류하고 로컬 커밋으로 모은다.
운영 서비스에는 로컬 main을 반영하며, 재시작 후 사용자가 새 GoTo를 요청해
실제 이동을 확인한다. 이전 main 병합의 원격 CI는 완료됐지만 이 추가 수정의
원격 CI를 실행했다는 뜻은 아니다.
