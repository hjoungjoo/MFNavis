# 포커스 계산과 UI 응답 개선

## 원인

IMX678 + 수동 초점거리 8.2409mm 설정은 2180×2180 원본을 사용한다.
기존 코드는 UI 프로세스에서 매 프레임 전체 후보의 배경·중심을 상세 계산했다.
2026-10-30 실내 영상에서는 7,773개 영역이 검출되고 크기 필터를 통과한
3,972개 후보를 상세 분석했다. 프레임당 2.41~3.66초가 걸렸고, 메인 스레드
20초 샘플 중 862/926개(93.1%)가 초점 계산 안에 있었다. 키 처리도 같은
이벤트 루프에서 실행되므로 계산이 끝날 때까지 기다렸다.

## 적용

- 원본 픽셀과 HFD/FWHM 식, 원본 배경·중심 측정 방식은 유지한다.
- 잡음 임계값 대비 신호와 원본 임계값 이상 픽셀 수로 후보를 먼저 추린다.
  후보가 많은 경우 상세 분석을 작은 후보 48개 + 큰 후보 16개로 제한한다.
  큰 초점 이탈 상태를 놓치지 않도록 큰 후보를 별도로 보존한다.
- 검출 수 표시는 축약 전 전체 크기 필터 통과 수를 유지한다.
- 배경·잡음 격자의 선형 보간/외삽은 float32로 처리해 전체 프레임 크기의
  float64 임시 배열을 줄인다.
- `focus_worker.py`의 독립 프로세스가 계산한다. 픽셀은 재사용하는 공유 메모리에
  복사하고 작은 요청·결과만 파이프로 전송한다. 진행 중인 작업은 최대 1개이며,
  완료 후 최신 프레임을 받는다. 최대 제출 빈도는 초당 5회다.
- UI는 결과를 기다리지 않는다. Image 화면은 카메라 프레임을 계속 갱신한다.
  Stars/Single/Stats는 계산에 사용한 정확한 프레임과 결과를 함께 표시한다.
  확대·축소·모드 변경은 같은 프레임을 다시 분석하지 않는다.
- 화면 이탈 시 작업 프로세스·파이프·공유 메모리를 정리한다. 프로세스 종료나
  8초 타임아웃은 오래된 수치를 지우고 다음 프레임에서 복구한다.
- 기존 표준 라이브러리·NumPy·SciPy를 사용하므로 추가 설치 의존성이나
  사용자 설치 옵션은 없다. 앱 재시작으로 적용된다.

## 검증

동일한 저장 프레임을 운영 앱이 실행 중인 장비에서 재측정했다.

| 항목 | 기존 | 개선 |
| --- | --- | --- |
| 2180×2180 계산 시간 | 2.41 / 3.66초 | 1.104 / 0.960 / 0.999초 |
| 상세 계산 후보 수 | 3,972 | 53 |
| 표시 검출 수 | 3,972 | 3,972 |
| HFD | 11.751397083695164 | 11.751397083695164 |

위 수치는 이 실내 프레임의 측정값이며, 모든 하늘 영상에서 같은 속도나
선택 결과를 보장하는 수치는 아니다. 후보가 64개 이하일 때는 기존처럼
모두 정밀 분석한다. 후보가 많은 경우 선택 순위가 달라질 수 있다.
축소 영상 탐색이나 별 주변만 재탐색하는 방식은 이번 변경에 포함하지 않았다.

자동 검증은 실제 spawned worker와 공유 메모리 정리, 입력 적체 방지,
오류·타임아웃·재시작, 오래된 결과와 새 프레임의 혼합 방지, 강제 재그리기,
원본 HFD 일치, 뜨거운 픽셀 제거, 큰 초점 이탈 후보 보존을 포함한다.
관련 테스트 161개 및 Nox lint/format이 통과했다.

운영 앱 적용 후 같은 방식의 20초 샘플링에서 메인 스레드의
`_find_blobs`/`_detection_threshold`/`_local_background` 샘플은 모두 0이었다.
메인 프로세스 CPU는 10초 측정 기준 91.2%에서 35.1%로 줄었고, 계산은
별도 worker에서 실행됐다. 사용자가 영상 갱신과 키 반응 모두 개선됐다고
확인했다. 최종 확인 시 서비스는 active, 자동 재시작 횟수는 0이었으며
포커스·공유 메모리 오류는 관찰되지 않았다.

실측 자료는 장비의 `~/MFNavis_data/test_data/focus-latency-20261030/`에 있다.
`frame-benchmark.json`은 기존, `optimized-frame-benchmark.json`은 개선본,
`focus-main.raw`와 `optimized-main.raw`는 메인 스레드 샘플이다.
`live-comparison.json`에 실행 중 비교와 사용자 확인을 기록했다.

## 영상 깨짐 별도 검사

이후 발생한 가로 띠·영상 어긋남은 MFNavis를 중지한 Picamera2 단독 촬영에서도
재현됐다. 버퍼 수와 프레임 간격을 바꾸어도 재현됐고, CSI 수신기의 D2 레인
오류와 CRC/ECC 오류가 반복 확인됐다. 오류 상태 레지스터는 읽으면 초기화되므로
반복 조회에서 관찰한 값은 이전 부팅의 잔여 기록이 아니다.

기존 케이블을 다시 꽂은 뒤에는 큰 영상 어긋남이 줄었지만 수신 오류가 남았다.
사용자가 케이블을 교체한 뒤 약 44초 동안 8회 조회한 모든 CSI 오류 플래그가
0이었고, 확인한 RAW 영상에서도 가로 띠와 어긋남이 사라졌다. 이 결과는 기존
케이블 또는 접촉 상태에 따른 신호 불량을 가리킨다. 이 증상 때문에 초점 가속
코드나 카메라 드라이버를 변경하지 않았다.

촬영 결과와 레지스터 기록은 장비의
`~/MFNavis_data/test_data/camera-integrity-20261030/`에 보관한다.
`csi-errors.json`은 점검 전, `reseated-long-results.json`은 재연결 후,
`replaced-results.json`은 케이블 교체 후 기록이다. 실내 원본 영상은 저장소에
포함하지 않는다.
