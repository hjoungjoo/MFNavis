# 개발 검증과 현장 확인

기준: 2026-10-10 작업 트리. 자동 회귀, 오프라인 재생, 실장비 검증의 범위를 구분한다.
과거 기능별 체크리스트의 완료 표시는 그 날짜의 결과이며 현재 전체 장비 보증으로 사용하지 않는다.

## 검사 실행

저장소 루트에서 시작한다. 활성화 스크립트는 `python/`으로 이동한다.

```bash
source scripts/activate_dev_trixie.sh
nox --no-venv -s lint format
nox --no-venv -s docs
```

기능 변경은 해당 기준 문서의 소스와 테스트를 따라 관련 회귀를 실행한다.
검사 확장이 필요한 변경은 전체 unit/smoke 세션과 장비 검증을 추가한다.
서비스 전환은 [테스트 운영 안내](../../TESTING_ko.md)의 명시적 요청 조건을 따른다.
문서 정리만으로 운영 서비스를 재시작하거나 실장 마운트를 움직이지 않는다.

## GoTo 시작부터 보정까지

[GoTo 기준 설계](mount_control_ko.md)의 연결 시나리오는 실제 서비스와 명령 epoch,
마운트 실행기를 연결하고 INDI I/O·관측·물리 정지만 시뮬레이션한다.
2026-10-10 앞선 코드 감사에서 관련 18개 suite **881 passed**를 확인했다.
이 값은 해당 코드 검증 기록이며 이번 문서 정리의 새 테스트 실행 결과와 구분한다.

핵심 경로를 다시 확인하는 명령:

```bash
pytest -q tests/test_goto_correction_lifecycle.py tests/test_indi_solve_fallback.py   tests/test_guide_holdover.py tests/test_mount_motion_limits.py
```

| 확인할 전이 | 기대 결과 |
|---|---|
| 새 GoTo와 초기 앵커 | 적합한 기준만 수락, Sync 응답 확인 뒤 슬루 |
| 실제 이동 종료와 광학 도착 | 정지 이후 촬영된 유효 solve로 오차 판정 |
| 큰 오차→근거리→도착 | 재GoTo→timed pulse→목표 정확도 확인 |
| 도착 전 솔빙 소실 | 추적 대기, 수동 이동 종료 위치 유지 |
| 무솔빙 사용자 정렬 | 도착 의도 저장, 첫 회복 solve로 실제 타겟 한 번 고정 |
| 도착 후 솔빙 소실 | 마지막 잔량·확인된 표류 처리, 중복 오차 누적 방지 |
| 솔빙 복구 | 새 실측 오차로 정상 보정/광학 복구 복귀 |
| 사용자 취소/Stop | 대기·타겟·자동 복구 해제, 해당 요청의 추적 정책 준수 |
| 어느 단계든 한계 초과 | 원인 표시, Abort·Tracking Off, latch 유지 |

## 현장 확인과 기록

현장에서는 실제 Sync 응답, 이동 정지 시각, 노출 종료 시각, 가이드 속도·펄스,
한계 감지부터 축 정지까지의 지연을 함께 기록한다.
구름/가림 중 장기 표류 정확도와 실제 방향키 해제 후 추적 유지도 별도 확인한다.
사용한 장비·설정·버전·RAW/메타데이터·관측지·시각·재현 순서를 남긴다.
실행 서비스/데이터 루트와 개발용 runtime을 구분하고, 사진·큰 RAW 자료는 Git에 넣지 않는다.

상태/프레임 수집과 A/B 재생의 상세 형식은 [검증 이력](../history/development/validation.md),
고정 실측은 [보고서](../mf_report/README.md)를 참조한다.
검출기 비교는 runtime provenance와 실행 binary identity를 함께 남겨 다른 버전을 비교하지 않도록 한다.
