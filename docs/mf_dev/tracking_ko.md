# 추적 제어의 종류와 소유권

기준: 2026-10-10 작업 트리. 아래 세 경로의 구현 상태를 구분해서 읽는다.

| 경로 | 구현과 시작 조건 | 솔빙/영상 소실 시 정책 |
|---|---|---|
| 기본 Tracking Guide | MFNavis GoTo/Guide 상태기계, 사용자 설정에 따라 활성 | 광학 도착 후 `GuideHoldover`; 기본 동작은 [GoTo 문서](mount_control_ko.md) |
| smooth tracking | `shadow`와 `active` 구현, MFNavis 모드·검증된 프로파일 등 조건 확인 | 관측 품질·허가 lease·검증된 coast 조건에 따라 별도 판정 |
| visual tracking 시험 | 확인된 환경의 `shadow`만 허용 | 별도 세션의 예측·재획득을 기록; 운영 마운트 보정 연결 없음 |

## 기본 추적 보정

네이티브 마운트 추적과 MFNavis의 추가 보정은 별개다. 기본 경로의 솔빙 실패 두 경우,
수동 이동과 사용자 정렬, 무기한 대기, 마지막 잔량과 표류 보정, 솔빙 복구는
[마운트 제어 기준 문서](mount_control_ko.md)에 하나의 상태기계로 정의했다.
별도 추적 방식의 품질 조건을 이 기본 경로의 실패 타이머로 사용하지 않는다.

## Smooth tracking

`smooth_tracking_runtime.start_session()`이 세션·타겟·광학 identity·연결 epoch·
제어 epoch·장비 응답 프로파일을 고정한다. `active` 시작은 검증된 응답/시각 프로파일을
요구하며, 명시적 펄스 캘리브레이션은 별도의 equipment/timing/Stop 검증 조건을 따른다.
`shadow`는 관측과 제안값을 비교하는 경로다. 기본 설정은 `mode=active`이지만
프로파일 기본값은 빈 객체여서 설정 문자열만으로 실장 보정이 승인되지 않는다.

`tick_policy()`는 관측·fault·신선한 mount 상태·Tracking On·비주차·비이동·
같은 연결 epoch를 확인한 뒤 짧은 `TrackingPermission`을 부여한다.
실행기는 각 패킷에서도 광학 나이와 드라이버 상태를 재확인한다.
active 세션이 제어권을 가지는 동안 기존 guide가 동시에 보정하지 않는다.
제어 epoch 변경은 사용자 명령으로 세션을 중지하고, 예전 허가를 재사용하지 않는다.

타겟 통합은 `smooth_tracking_target_integration_enabled=false`가 기본이다.
통합을 켜면 기존 천체 identity/에페메리스를 사용하고 RA·Dec 시간 변화를 반영한다.
통합 세션의 axis/GoTo recovery는 꺼지며 임의의 회복 슬루를 보내지 않는다.
coast는 확인된 프로파일과 허용된 관측 소실 사유가 있는 경우에만 승인한다.
모든 smooth timed pulse에도 공통 이동 한계 인터록이 적용된다.

## Visual tracking 시험과 후속 설계

`visual_tracking_runtime.read_manifest()`는 `schema=1`, `mode=shadow`,
장비 확인, Alt/Az 또는 EQ, camera/lens/calibration identity, RAW 크기와
roll 확인, 만료 시각, 최대 프레임 수, 별도 절대 출력 경로를 검사한다.
달 직접 측정은 독립적으로 확인한 원반 반지름이 필요하다. 같은 프레임의 RAW와
검출·메타데이터를 pairing하며, 환경 파일만으로 실장 검증 완료를 선언하지 않는다.
[환경 예제](visual_tracking_environment.example.json)는 실제 장비 값으로 확인해야 한다.

달 근접 stage GoTo 제안, 라이브 스택 안정화 조사, 과거 visual 전체 설계의
미완료 단계는 일반 GoTo에 이미 구현된 기능으로 설명하지 않는다.
미구현안의 세부와 trial/demo/replay 절차는 [마운트 이력](../history/development/mount.md)을 참조한다.

솔빙 실패 프레임의 별 대응으로 상대 이동을 측정하고 기본 추적 보정에 연결하는
후속 설계는 [별 영상 기반 상대 추적](solver_ko.md#솔빙-실패-시-별-영상-기반-상대-추적-개발-설계)을 따른다.
이 통합 설계는 미구현이며 현재 visual shadow의 운영 제어권을 변경하지 않는다.

## Smooth와 상대 영상 추적의 통합 계획

2026-10-11 사용자 요구 반영. **기본 GoTo와 추적 보정 수정이 끝난 뒤 진행할
후속 작업**이다. 현재는 요구사항만 기록한다. 운영 코드 통합, INDI 화면 이동,
설정 변경은 아직 수행하지 않으며 추가 테스트·검증은 사용자가 요청할 때 진행한다.
기본 작업이 끝났다는 추정만으로 통합이나 장비 시험을 자동 시작하지 않는다.

기존 Smooth에는 실제 보정 실행 경로가 있다. 이번에 작성한
`benchmark_visual_fallback.py`와 `benchmark_weak_star_fallback.py`는 오프라인
시험 코드다. 같은 목적의 경로를 별도 제품 기능으로 늘리지 않고, 기본 GoTo/Guide의
완료된 수명주기에 기존 Smooth의 영상 측정·실행 경로와 필요한 시험 결과를 통합한다.

### 통합 범위

- 기존 Smooth의 장비 응답, 관측 시각·품질 검사, 보정 실행과 제어권 관리를
  재사용한다. 진행 중인 기본 GoTo/Guide 수정 결과를 먼저 확인해 중복 상태기계,
  이중 보정, 잘못된 기준점 전환을 정리한다.
- 무솔빙 GoTo 대기 중 Align을 받으면 사용자 도착 확인으로 처리하고,
  이동 종료·정착 이후 현재 영상 위치를 기준으로 보정한다. 첫 유효 솔빙이
  복구되면 그 실제 좌표를 한 번만 추적 타겟으로 채택한다. 자세한 계약은
  [솔빙 실패 상대 추적 설계](solver_ko.md#무솔빙-goto-대기-중-정렬-처리)를 따른다.
- 별이 적고 희미한 환경을 주 사용 조건으로 삼는다. 시험한 로컬 ROI 탐색,
  별 분포·모양 검사와 짧은 영상 누적을 통합 후보로 삼되, 시험용 전체 영상
  복사나 최소 별 수·SNR 값을 그대로 운영 경로에 옮기지 않는다. 기존 ROI 전달과
  검출 결과를 재사용하고 누적 관측의 실제 시각을 보존한다.
- 불필요하거나 목적과 충돌하는 설정·동작은 정리한다. 영상이 불충분하면
  보정을 보류하며, Stop·새 GoTo·반복 Align과 솔빙 복구의 처리 소유자는 하나로 한다.
  달·행성 등 기존 지원 기능은 공통 타겟 처리와의 호환성을 확인한다.

### INDI 화면과 최소 설정

통합 시 현재 **Smooth optical tracking 영역을 INDI 페이지의 마지막 기능 영역으로
이동**한다. 기본 GoTo와 추적 조작 흐름을 먼저 배치한다.

일반 화면에는 영상 추적 보정의 사용/해제 설정과 현재 상태·대기 이유를 중심으로
남긴다. 타겟 좌표·천체 종류·정렬은 기존 GoTo/Align 정보를 재사용하고 같은 값을
다시 입력하게 하지 않는다. 시작·중지는 기존 추적 조작과 연결해 중복 버튼을 정리한다.
사용 설정 자체가 새 GoTo나 캘리브레이션 이동을 시작해서는 안 된다.

현재의 Off/Shadow/Active 선택, 별도 타겟 통합 체크박스, RA·Dec 재입력,
장비 프로필 JSON 업로드·다운로드, 캘리브레이션은 일반 사용의 필수 절차로 요구하지 않는
방향으로 정리한다. 필요한 개발·장비 설정은 별도 진단 경로로 분리한다.
장비 응답과 광학 정보의 유효성 검사는 유지하고, 준비되지 않았으면 필요한 조치를
상태로 표시한다. 설정 단순화를 위해 미검증 값을 자동 승인하지 않는다.

표시 상태는 솔빙 기반 보정, 영상 기반 보정, 영상 부족 대기, 사용자 중지를
구분한다. 세부 별 수·오차·거부 원인은 진단 정보로 제공한다.
이 절은 후속 화면 설계이며 현재 웹 UI가 이미 바뀌었다는 뜻은 아니다.

## 현재 위치 자동 캘리브레이션 구현 설계

설계 기준일: 2026-10-12. 코드 기준: `63cb75d0`. **아래 기능은 구현 예정이며,
현재 제공되는 기능이나 실장 검증 완료 결과가 아니다.** 일반 GoTo와 추적의 현재
동작은 이 문서 앞부분과 [마운트 제어 기준](mount_control_ko.md)을 따른다.

사용자는 별이 보이는 방향으로 망원경을 이동한 뒤 **현재 위치에서 자동
캘리브레이션**을 요청한다. MFNavis는 그 위치 주변에 시험 좌표를 만들고,
작은 GoTo와 양방향 펄스 이동·복귀를 수행하여 장비 응답과 보정 계수를 측정한다.
검증된 후보만 저장하고 시작 위치로 복귀한다. 별 이름, 기준별 2~3개, 사전 측정된
PID 값, 장비 프로파일 JSON을 사용자에게 요구하지 않는다.

설계의 목적은 특정 OnStep 장비에 맞는 상수를 찾는 것이 아니라 다양한 마운트와
광학 구성에서 빠른 중심 접근과 안정적인 중심 유지를 함께 달성하는 것이다.
캘리브레이션은 선택 기능이다. 실행하지 않은 장비는 제한된 기본 PID로 사용하고,
향후 정상 보정에서 확인된 응답을 점진적으로 학습할 수 있도록 구성한다.

초기 구현의 실행 범위는 MFNavis GoTo 모드다. `indi_mount`의 네이티브 GoTo만으로는
MFNavis PID를 튜닝하지 않으며 모드를 몰래 전환하지 않는다. 장비 종류가 다양하다는
요구는 특정 제조사에 고정하지 않는다는 뜻이고, 모든 드라이버가 필요한 펄스·좌표·
시각 기능을 제공한다는 뜻은 아니다.

### 범위와 완료 조건

- MFNavis가 보내는 광학 보정과 timed guide pulse를 튜닝한다. 마운트 펌웨어의
  내부 모터 PID, 극축 정렬, SkySafari Align, `target_pixel` 정렬은 변경하지 않는다.
- 작은 GoTo의 이동 시간과 도착 후 MFNavis 미세 보정 시간을 별도로 평가한다.
  전체 GoTo 시간 감소를 PID 개선으로 곧바로 해석하지 않는다.
- 기본 구현은 고정된 항성 시야를 사용한다. 달·행성을 자동 선택하거나 추적할
  필요는 없으며, 이동 천체의 영상은 항성 응답 학습에서 제외한다.
- 캘리브레이션이 끝나면 결과, 검증한 방향·속도·위치 범위, 복귀 성공 여부를
  표시한다. 후보 채택과 시작 위치 복귀는 서로 다른 완료 조건이다.
- 기본값보다 개선을 입증하지 못해도 정상적인 결과다. 이 경우 기존값을 유지하고
  `개선 미확인` 또는 `측정 부족`으로 끝낸다. 무한 반복으로 계수를 찾지 않는다.

기존 smooth 캘리브레이션은 `equipment_verified` 또는 검증된 프로파일과
시각·Stop 조건을 요구하며, 측정한 후보도 바로 활성화하지 않는다. 새 절차에서
이 조건을 없애거나 응답이 좋아 보인다는 이유로 `verified=true`를 넣어서는 안 된다.
**장비 명령·시각 계약 확인과 광학 응답 학습은 분리한다.** 응답 프로파일이 없어도
시작할 수 있도록 하되, 드라이버별 bounded pulse·정지·좌표 프레임 계약을 확인할 수
없는 장비는 측정/진단만 제공하고 자동 시험 이동은 시작하지 않는다.

현재 smooth 경로의 P 계수와 기본 `GuidePID` 계수는 같은 의미가 아니다.
시간 적용 방식과 출력 단위가 다르므로 숫자를 그대로 복사하지 않는다.

### 사용자 화면과 시작 계약

INDI 화면의 추적 설정 영역에 선택 기능으로 `현재 위치에서 자동 캘리브레이션`을
둔다. 평상시 GoTo와 추적 사용에 이 절차를 강제하지 않는다. 시작 전 화면에는
자동 이동하는 최대 반경, 시험 시간 상한, 정상 완료 시 시작 위치 복귀를 표시한다.
버튼 실행은 표시된 범위의 자동 시험을 요청하는 행위이며 매 GoTo마다 다시 묻지 않는다.

진행 표시는 `관측 확인 → 응답 측정 → 후보 계산 → 비교 검증 → 시작 위치 복귀`로
단순화한다. 대기 이유와 중지 버튼을 항상 제공하며, PID·공분산·epoch는 진단 화면에
둔다. 연결 상태는 기존 상단 메뉴바에, 캘리브레이션 대기 이유는 Push 하단 상태줄에도
표시한다. 이동량의 S/I/M 표시는 기존 좌표 출처 표시 계약을 유지한다.

시작 요청 시 아래 정보를 하나의 세션에 고정한다.

- 새 `session_id`, 장비·연결·제어 epoch, 광학 geometry와 정렬 revision.
- 최신 유효 `pointing.aligned.solve`의 항성 좌표, 좌표 프레임, 촬영 시각, 시야 정보.
  이것이 복귀 위치 `P0`다. 카메라 축 중심이나 IMU 진행값으로 바꾸지 않는다.
- 기존 사용자 타겟 identity, 추적 의도, 기존 계수·프로파일 hash.
- 유효한 위치·시각 정보, 장비 한계, 자동 이동 반경과 누적 이동·시간 예산.

좌표 GoTo 시험에는 시작 시 유효한 절대 솔빙이 필요하다. 솔빙이 없으면 `관측 확인`
상태에서 기다리며 IMU·마운트 표시 좌표만으로 학습용 주변 좌표를 생성하지 않는다.
이는 **이 캘리브레이션의 시작 조건**이며 무솔빙 일반 GoTo/추적 정책을 바꾸지 않는다.
GPS 장치 연결 자체를 필수로 만들지 않고 기존의 유효 위치·시각 판정을 재사용한다.

### 시험 좌표와 이동 범위

`P0` 주위 고정 접평면의 동·북 방향 각도 오프셋으로 시험점을 정의한다.
순서는 `P0 → +E → P0 → -E → P0 → +N → P0 → -N → P0`를 기본으로 한다.
이후 반복에서는 순서를 반대로 하여 시간에 따른 날씨·장비 변화의 영향을 비교한다.
별 이름이나 카탈로그 항목을 새로 만들지 않는다.

오프셋은 구면 좌표 변환으로 RA/Dec에 옮긴다. RA 값에 같은 도수를 단순 가산하지
않으며 0/360도 경계, 고적위, Alt/Az 변환, 좌표 epoch를 공통 좌표 계층에서 처리한다.
이동 중 시야 회전은 별들의 변환 모델에 포함하고 중심 이동으로 오인하지 않는다.

반경은 아래 제약을 모두 만족하도록 계획한다.

- `r_max`: 시작 화면에서 제시한 반경, 현재 장비 한계, 유효 시야·별 대응 가능 범위의
  교집합. 시야가 넓다는 이유로 사용자가 허용한 이동 범위를 넓히지 않는다.
- `r_initial`: `r_max` 안에서 보수적으로 시작하는 반경. 관측 오차보다 충분히 큰
  실제 이동이 확인되지 않으면 제한된 횟수만 확장한다.
- 펄스 시험은 필요한 별들이 프레임/ROI 경계 밖으로 사라지지 않을 여유를 둔다.
  GoTo 후 재솔빙할 때와 연속 ROI 대응이 필요할 때의 이동 한계를 별도로 계산한다.
- 양방향 시험이 모두 가능한 공통 반경을 우선한다. 불가능한 방향은 미검증으로
  표시하며 다른 방향 측정값으로 채워 넣지 않는다.

주변이 모두 보인다고 추정하지 않는다. 특정 방향에서 구름·장애물로 영상이 사라지면
추가 좌표 탐색과 반경 확대를 보류한다. 기존 한계 인터록을 모든 GoTo와 펄스에 적용하고,
초기 버전은 캘리브레이션 때문에 자오선 반전이나 천정 부근의 급격한 축 전환을 요구하는
경로를 만들지 않는다. 지원하지 않는 기하 조건이면 위치 변경이 필요한 이유를 표시한다.

### 측정과 튜닝 절차

1. **관측 기준선:** 네이티브 마운트 추적을 유지한 채 유효한 독립 프레임들로
   표류와 측정 산포를 추정한다. 다른 보정기가 같은 기간에 움직였다면 해당 명령을
   모두 기록하거나 기준선 측정에서 제외한다. 카메라 자동 노출·게인은 고정하지 않는다.
2. **기본값 기준 시험:** 현재 검증값 또는 기본 PID로 주변 GoTo와 복귀를 실행한다.
   송신 성공, 드라이버 수락, 물리 이동 종료, 광학 도착을 각각 기록한다.
3. **장비 응답 측정:** 동일 방향의 짧은 펄스와 방향 반전 후 펄스를 분리하여 측정한다.
   허용 범위 안의 두 가지 이상 길이를 비교하고, 방향·길이별 유효 반복을 확보한다.
   기존 각 방향 3회는 최소 시작점이며 신호/잡음과 반복 일치도 검사를 통과해야 한다.
4. **추정기 선정:** 시각·응답 모델을 먼저 확인하고 기존 필터와 칼만 필터 후보를
   비교한다. 이 단계에서는 PID를 고정한다.
5. **PID 후보 계산:** 선택한 추정기와 실행 모델을 고정한 채 축별 P, 필요한 I와 D,
   중심 부근 보정 기준을 제한된 후보 집합에서 비교한다. 기존값도 후보에 포함한다.
6. **독립 검증:** 학습에 사용하지 않은 복귀 시험과 중심 유지 구간에서 후보를 평가한다.
   실제 시작 오차·방향·관측 품질이 비슷한 기존값/후보값 시험끼리 비교한다.
7. **채택과 복귀:** 검증 통과 후보를 원자적으로 저장하고 정상 GoTo 경로로 `P0`에
   복귀한다. 광학 복귀가 확인된 뒤 시작 위치를 기준으로 추적한다.

GoTo가 너무 정확하여 PID 보정이 거의 없었다면 `좋은 PID`라는 결론을 내리지 않는다.
작은 펄스로 측정 가능한 초기 오차를 만든 후 같은 고정 목표로 복귀시켜 평가한다.
강제 오프셋 동안 자동 보정이 이를 상쇄하지 않도록 제어권을 시험 실행기에 한정한다.
시험용 펄스 포화와 장비 용량 부족도 별도로 기록한다.

### 제어권과 상태 전환

세션 조정자는 시험 순서와 평가를 관리하고, 모든 이동은 기존 서비스와 실행기를
통한다. HTTP 또는 UI에서 드라이버를 직접 호출하지 않는다. 일반 PID와 smooth가
동시에 펄스를 보내지 않도록 한 시점에 하나의 보정 소유자만 허용한다.

| 상태 | 이동과 전환 조건 |
|---|---|
| `IDLE` | 요청 없음. 자동으로 캘리브레이션을 시작하지 않음 |
| `PRECHECK` | 장비 계약·한계·기존 이동 종료 확인. 실패하면 사유와 함께 종료 |
| `ACQUIRE` | 유효 솔빙과 기준선 확보. 조건 충족 후 계획 생성 |
| `BASELINE` | 기존값으로 시험. 정상 GoTo 완료 판정과 동일한 광학 증거 사용 |
| `IDENTIFY` | 정해진 펄스 시험과 응답 수집. 현재 단계 외 보정 명령 차단 |
| `FIT` | 후보 계산. 시험 이동 없음, 네이티브 추적 유지 |
| `VALIDATE` | 세션 내부 후보로 비교. 영구 설정에는 아직 쓰지 않음 |
| `COMMIT` | 품질·개선·문맥 일치 검사 후 후보 저장 또는 기존값 유지 |
| `RETURN` | 문맥·좌표·한계가 유효할 때만 `P0`로 정식 GoTo |
| `COMPLETE` | 결과와 광학 복귀가 확인됨 |
| `WAIT_OBSERVATION` | 새 시험 명령 보류. 구름이 걷히면 기준선을 다시 확보한 후 재시도 |
| `INCOMPLETE` | 예산 소진, 연결 변경, 복귀 불가 등. 결과와 미완료 사유 기록 |
| `ABORTED` | 사용자 정지·새 GoTo·수동 조작·Align 등으로 취소. 자동 복귀 없음 |

`WAIT_OBSERVATION`에서는 진행 중 명령의 실제 종료를 확인하고 이전 단계의 부분
측정 쌍을 폐기한다. 끊긴 관측 전후를 같은 펄스의 응답으로 연결하지 않는다.
재개 시 세션 이동 범위와 동일 문맥을 재검사하며 시간·시도 예산을 리셋하지 않는다.

Stop은 후보 계산·파일 저장·대기·복귀 중에도 최우선이다. 제어 epoch를 갱신하여
미전송 명령을 무효화하고 기존 장비 Stop 계약을 실행한다. 뒤늦은 완료 응답이나
최적화 결과가 세션을 부활시키거나 프로파일을 저장하게 해서는 안 된다.
`COMMIT`은 원자적 적용 시점 직전에 epoch를 재검사한다. 이미 적용이 끝난 뒤 Stop이
왔으면 적용 사실은 기록하되 이후 이동은 실행하지 않는다.

연결 상실 시 캘리브레이션 명령과 학습은 보류/종료하지만, 이를 근거로 사용자의
일반 추적 의도·타겟을 삭제하거나 네이티브 추적 OFF를 보내지 않는다. 수동 Push 관측도
유지한다. 재연결은 다른 연결 epoch이므로 중단된 시험을 자동 재개하지 않는다.

정상 완료의 `P0` 복귀는 시작 요청에 포함한다. 명시적 정지나 새 사용자 명령 이후에는
복귀하지 않는다. 실패 종료에서도 좌표와 제어권이 확인되지 않으면 복귀를 강행하지
않고 `복귀 미완료`로 표시한다. 카탈로그 선택은 보존할 수 있지만 과거 선택 타겟이
`P0`와 다르면 그 타겟으로 추가 이동하거나 그 타겟을 추적 중이라고 표시하지 않는다.

각 시험 GoTo는 정상 GoTo의 위치·시각 처리, 상태 발행, 화면 전환, 도착 판정을 거친다.
`session_id`와 `trial_id`를 가진 내부 자식 요청은 조정자가 발행한 것으로 구분하고,
외부 새 GoTo는 세션을 취소한다. 내부 요청에도 기존 epoch 검사를 적용하되, 그 요청
자체를 외부 사용자 취소로 오인하지 않도록 명령 소유권 계약을 확장한다.

일반 서비스 재시작은 초기 상태로 시작하며 타겟·이동·캘리브레이션을 자동 재개하지
않는다. 중단 기록은 분석용으로만 읽는다. 사용자가 명시적으로 요청한 테스트 유지
재시작만 정상 GoTo로 재진입하고, 캘리브레이션은 새 문맥의 새 세션으로 다시 시작한다.

### 좌표와 시각을 포함한 측정 계약

아래 계약은 신규 제안이다. 실제 타입 이름과 저장 스키마는 구현 시 확정하되 의미와
단위를 유지한다. 기존 `TrackingContext`, `CaptureTiming`, `TrackingMeasurement`,
`CorrectionPlan`, `CorrectionReceipt`에 이미 있는 필드는 재사용한다.

| 레코드 | 필수 내용 |
|---|---|
| `CalibrationSession` | schema, session ID, 상태와 사유, 시작 좌표/프레임, 원래 사용자 의도, 장비/광학 identity, 각 epoch, 원래 프로파일 hash, 이동·시간 예산과 사용량 |
| `CalibrationTrial` | trial ID, 단계, 목표 오프셋, 실제 시작 오차, 접근/반전 방향, 적용한 제어기·추정기 hash, 시작·종료 시각, 성공/제외/실패 사유 |
| `CalibrationObservation` | frame key, 촬영 시작/끝/중간 시각과 불확실성, 절대/상대 좌표 출처, 오차, 품질·별 수·잔차·SNR, 노출·게인, geometry/reference ID |
| `ActuationObservation` | command ID, 실제 방향·속도·기간, 송신/수락/시작/종료 시각의 범위, 중간 단축·취소·포화·불명확 결과, 관측 구간과 겹친 실행량 |
| `CalibrationCandidate` | 부모 프로파일 hash, 응답 모델과 유효 범위, 추정기 설정, 축별 PID와 단위, 평가 지표·불확실성, 후보/검증/채택 상태 |
| `CalibrationResult` | 채택 여부, 기존값/후보값 비교, 제외된 시험 수와 사유, 미학습 방향, 복귀 결과, 로그·영상 manifest 경로 |

제어 시간 계산은 같은 clock epoch의 monotonic 시각을 사용한다. UTC는 관측 위치 변환과
기록 표시에 사용한다. 프레임 수신 시각을 촬영 시각으로 대신하지 않는다. 노출이 길면
그 프레임은 시간 구간의 평균 관측이라는 점과 midpoint 근사의 오차를 반영한다.

단위는 접평면 위치 오차 `arcsec`, 표류 `arcsec/s`, 펄스 `ms`, 지연·주기 `s`로
통일한다. `1′ = 60″`, `1° = 60′`이며 각분을 시간 초와 혼동하지 않는다.
RA가 시간 단위인 외부 프로토콜은 경계에서 도 단위로 변환한다.

같은 `(capture_epoch, sequence)`는 한 번만 소비한다. 동일 프레임에서 얻은 솔빙과
ROI 위치는 독립 관측이 아니므로 두 번 갱신하지 않는다. 다른 프레임의 솔빙도 같은
기준 영상 오차를 공유할 수 있어 상관을 고려한다. 상대 영상 정밀도는 절대 좌표
정확도를 대체하지 않으며, IMU/마운트 좌표를 광학 응답의 정답으로 사용하지 않는다.

초기 식별은 펄스 전·후의 깨끗한 관측을 사용한다. 후 관측의 노출 시작이 실행 종료
상한과 정착 시간 이후여야 한다. 노출과 펄스가 겹친 구간을 활용하는 고급 식별은
실행량을 적분하는 시간 모델을 검증한 뒤 추가한다. 늦게 도착한 관측은 초기 버전에서는
폐기하고 사유를 기록한다. 현재 상태를 과거 위치로 되돌리지 않는다.

### 장비 응답 모델

고정 목표 접평면에서 `e = 목표 - 관측 위치`를 동·북 방향 오차로 정의한다.
`B`는 N/S/E/W 각 펄스가 만드는 오차 감소량이며 크기는 `2×4`, 단위는 `arcsec/ms`다.
이름이 north인 명령이 영상에서 반드시 +N으로 움직인다고 가정하지 않고 실제 측정한
열벡터를 사용한다. 기존 코드의 오차 부호와 이 정의의 변환을 어댑터 테스트로 고정한다.

```text
e_after = e_before + drift * dt - B * pulse_ms + residual
measured_correction = e_before - e_after + drift * dt
```

초기 버전은 방향별 가중 중앙값/강건 회귀로 `B`를 추정한다. 방향 간 결합도 보존하며
정·역방향을 완전히 대칭이라고 가정하지 않는다. 신뢰 가능한 방향만 활성화한다.
반전 직후와 같은 방향 연속 펄스를 분리하여 백래시·최소 유효 펄스를 측정하고, 영상
주기가 너무 길어 지연과 백래시를 구분할 수 없으면 해당 항목은 `unknown`으로 둔다.

가이드 속도별 응답을 구분한다. 두 축이 공유하는 실제 적용 속도와 요청 속도가
다르면 실제 적용값을 기록한다. 명령 ms만 보고 이동량을 학습하지 않는다.
펄스 길이 또는 속도에 따라 선형성이 깨지면 검증 범위를 줄이거나 구간 모델을 사용한다.

응답 행렬의 유효 축 rank, 조건수, 부호 일관성, 반복 산포와 측정 신호 크기를 검사한다.
작은 반응을 무조건 느린 모터로 판단하여 펄스를 늘리지 않는다. 포화·백래시·구름·실행
불명확 중 무엇인지 확인할 수 없으면 학습을 보류한다. EQ의 Dec 한쪽 방향 보정 정책을
Alt/Az의 두 축에 그대로 적용하지 않는다.

정상 관측 중 RLS 등 순차 추정은 후속 단계다. 폐루프 데이터에는 측정 잡음과 명령의
상관이 생길 수 있으므로 단순 오차/펄스 비율을 그대로 누적하지 않는다. 식별 가능한
명령 변화, 독립 검증 오차와 신뢰도를 함께 검사하고 정보가 부족한 방향은 갱신하지
않는다. RLS를 적용했다는 사실만으로 모델의 수렴을 보증하지 않는다.

### 칼만 필터와 PID 연결

초기 칼만 필터는 고정 접평면의 위치 오차와 **명령에 의한 이동을 제외한 표류 속도**를
상태로 둔다. 구면 좌표 자체에 선형 필터를 적용하지 않고 작은 국소 영역에서 사용한다.

```text
x = [e_E, e_N, v_E, v_N]
F(dt) = [[I2, dt * I2], [0, I2]]
delta = B * actual_pulse_ms
x_pred = F(dt) * x - [delta[0], delta[1], 0, 0]
P_pred = F(dt) * P * F(dt).T + Q(dt) + Q_actuation
z = [observed_e_E, observed_e_N]
H = [I2, 0]
innovation = z - H * x_pred
S = H * P_pred * H.T + R_frame
K = P_pred * H.T * inv(S)
x_updated = x_pred + K * innovation
P_updated = (I4 - K * H) * P_pred * (I4 - K * H).T + K * R_frame * K.T
```

표기의 제어 입력은 위쪽 두 위치 성분에만 `B * actual_pulse_ms`를 빼는 4차원
벡터다. `actual_pulse_ms`는 예측 구간과 겹친 실행량이며 요청량이나 전체 예약량이
아니다. 실행 시각이 불명확하면 그 구간에서 장비 응답을 학습하지 않고 예측 불확실성을
늘린다. 같은 명령을 `GuideHoldover`에서 다시 차감하지 않는다.
`Q_actuation`은 응답 모델·실행량·시각의 불확실성을 상태 공분산에 전달한다.
갱신식은 관측 품질 검사를 통과했을 때만 적용한다. 실제 구현은 행렬 역행렬을 직접
계산하는 대신 선형계 풀이를 사용하고 공분산의 대칭성·양의 준정부호를 검사한다.

- `dt`는 실제 관측 간격을 사용한다. `Q(dt)`도 이 간격에 맞춰 이산화한다.
  표류 가속도 백색잡음 모델을 쓰면 각 축의 위치/속도 블록은
  `q * [[dt^3/3, dt^2/2], [dt^2/2, dt]]`로 구성할 수 있다.
- `R_frame`은 centroid/별 정합 잔차, 별 분포, 노출 중 번짐과 시각 불확실성을
  이용해 추정한다. 기존 `bound_arcsec`는 보수적 오차 한계이므로 이를 그대로
  표준편차라고 가정하여 제곱하지 않는다. 절대 기준의 공통 오차도 별도로 유지한다.
- 필터의 Q/R은 관측 자료로 제한된 범위에서 조정한다. 노출·게인 변경만으로 장비
  응답 B를 초기화하지 않지만 배율·회전·ROI 좌표계 등 geometry 변경은 재검증한다.
- `innovation.T * inv(S) * innovation`과 영상 품질을 함께 검사한다. 큰 실제 이동을
  계속 이상치로 버리지 않도록 연속된 독립 관측의 방향 일치 시 재획득/상태 재초기화를
  허용한다. 사용자 수동 이동·Align은 앞의 취소 계약을 따른다.
- 제어용 필터와 별도로 원래 광학 측정을 기록한다. 필터 출력을 정답으로 삼아
  같은 필터의 개선 여부를 판정하지 않는다.
- 구름 사이 예측은 불확실성이 증가한다. 캘리브레이션은 예측만으로 다음 시험이나
  도착 판정을 진행하지 않는다. 일반 추적의 기존 holdover 정책은 별도로 유지한다.

보정 시에는 촬영 시점의 상태를 명령 실행 예상 시점으로 전달해 지연을 보상한다.
확인된 표류를 선행 보정할 수 있으나 기존 drift/holdover와 하나의 경로로 통합한다.
PID의 D 항은 추정한 접근 속도를 활용할 수 있다. 위 상태의 `v`는 표류 속도이므로
그 자체를 오차 변화율로 쓰지 않고 실행 중 보정의 이동 속도를 함께 반영해야 한다.
기존 D 항을 대체할 때는 부호·단위·중복 감쇠 여부를 따로 검증한다.

기존 `GuidePID`는 오차 arcsec를 보정량 arcsec로 바꾼다. 같은 정의를 유지하면
P는 무차원, I는 `1/s`, D는 `s`다. 출력이 속도인 제어기로 바꾸면 별도 스키마/버전이
필요하다. 첫 구현에서는 현재 anti-windup, 중복 프레임 방지, 출력 제한을 유지한다.
기본값·PI 후보·PID 후보를 비교하며 D가 항상 필요한 것으로 가정하지 않는다.

중심 근처에서는 측정 신뢰 범위와 허용 오차에 기반한 deadband 및 재진입 hysteresis를
사용한다. 예측 이탈이 허용 범위에 접근할 때만 보정하되 실제 광학 측정을 계속 감시한다.
분당 펄스 수만 줄이기 위해 지나치게 긴 펄스나 큰 중심 이탈을 허용하지 않는다.

### 후보 채택과 수치 설정

측정·필터·PID를 동시에 자유롭게 최적화하지 않는다. 응답 모델 → 추정기 → PID 순서로
고정해 가며 후보를 평가한다. 제한된 후보 수와 사전에 정한 세션 시간 안에서 수행한다.
기록 재생은 관측 처리와 후보 선별에 사용한다. 다른 제어기가 만들었을 미래의 실제
이동은 같은 영상 재생만으로 알 수 없으므로, 최종 폐루프 비교는 장비 시험이 필요하다.

| 지표 | 측정 정의와 사용 |
|---|---|
| 중심 도달 시간 | 미세 복귀 시작부터 허용 오차 안에서 유지 조건을 처음 충족한 시점까지. 네이티브 GoTo 시간은 별도 기록 |
| 중심 유지 오차 | 독립 광학 측정의 중앙값·95백분위·최대값, 유효 관측 비율과 함께 평가 |
| 과도 응답 | 목표 통과 후 최대 반대편 오차, 재진입 횟수와 정착 시간 |
| 명령량 | 분당 펄스 수, 총 실행 시간, duty, 방향 반전 수. 노출 주기와 함께 기록 |
| 성공률 | 계획한 시험 중 성공·실패·제외 수. 구름 구간을 제거해 실패가 사라진 것처럼 집계하지 않음 |
| 불확실성 | 반복 간 산포, 응답 추정 오차와 비교 구간. 개선 폭이 산포보다 작으면 개선 미확인 |

기존값 A와 후보 B는 가능한 한 `A-B-B-A` 순서로 비교하고 실제 시작 오차와 방향별로
묶는다. 노출·품질 조건이 비교 불가능하게 달라지면 결과를 보류한다. 날씨가 시간에
따라 달라지는 관측으로 정확한 개선 백분율을 확정하지 않는다.

채택은 아래 조건을 모두 만족해야 한다.

1. 예산·장비 한계·명령 문맥 위반이 없고, 학습과 검증 구간이 분리되어 있다.
2. 검증 방향별 도착 성공률과 중심 유지 오차가 설정한 허용 범위를 만족한다.
3. 중심 접근 개선 또는 명령량 감소가 반복 산포와 사전에 정한 최소 개선 폭을 넘는다.
4. 더 빠른 접근을 위해 과도 응답·95백분위 유지 오차를 허용치보다 악화시키지 않는다.
5. 중지·연결·광학 문맥이 그대로이며 후보의 부모 프로파일이 현재값과 일치한다.

개발 시 다음 설정을 명시적으로 정의하고 세션 시작에 고정한다. 수치는 시뮬레이터와
현장 검증으로 선정할 **설계 파라미터**이며 이 문서에 없는 보편적인 최적값을 가정하지
않는다. 장비 실행 제한은 기존 검증된 제한과의 교집합으로만 적용한다.

| 설정 묶음 | 항목과 결정 기준 |
|---|---|
| 이동 범위 | 최대 반경·초기 반경·누적 이동, 카메라 시야 여유와 기존 한계 |
| 실행 예산 | 최대 GoTo/펄스/재시도/후보 수, 세션 시간·관측 대기 상한 |
| 식별 품질 | 방향·길이별 반복 수, 신호 대비 관측 오차, 조건수·반복 산포 상한 |
| 계수 변경 | 축별 P/I/D 상하한, 갱신당 변화율, 필터 Q/R 범위 |
| 완료 판정 | 사용자 목표 정확도, 도착 후 유지 시간과 독립 프레임 수 |
| 후보 채택 | 최소 개선 폭, 유지 오차·과도 응답·성공률 허용치 |

완료 판정에서 영상 정밀도가 사용자 목표 정확도보다 나쁘면 정확도를 자동으로
완화하여 성공 처리하지 않는다. `현재 관측 정밀도로 판정 불가`로 기록한다.

### 프로파일 저장과 관측 중 적응

프로파일 키에는 장비/드라이버 identity, 마운트 방식, 가이드 속도, 광학 geometry,
카메라 배율·방향, 정렬 revision, 응답/제어기 버전을 포함한다. 관측 위치·고도·방위,
EQ의 pier side, 측정 시각, 검증한 속도·방향 범위는 유효성 정보로 저장한다.
사용자가 바꿀 수 있는 하중·균형 등은 완전히 자동 감지할 수 없으므로 재사용 시 실제
응답 일치도를 확인한다. 노출·게인은 관측 조건 기록이며 값이 바뀌었다는 이유만으로
장비 프로파일을 모두 폐기하지 않는다.

`candidate → validated → active` 상태를 분리하고 기존 프로파일을 보존한다.
임시 파일 기록, flush/fsync, atomic replace 등 기존 저장소 관례에 맞는 원자적 저장을
사용한다. 쓰기 실패 시 기존 active를 유지한다. 런타임 적용 때도 같은 버전의 응답·필터·
PID를 함께 선택하고 이전 적분 상태를 그대로 새 계수에 곱해 출력이 튀지 않도록 한다.

현재 위치 주변에서 얻은 프로파일을 전 하늘 보증으로 저장하지 않는다. 다른 위치로
GoTo하면 좌표 기저 변환과 물리 응답의 유효성 확인을 분리한다. 기저를 회전할 수
있다는 것만으로 다른 고도·축 속도에서 같은 응답이라고 판단하지 않는다. 범위 밖에서는
기본값/기존 유효 프로파일로 동작하고, 정상 명령의 결과가 쌓이면 검증 범위를 확장한다.

후속 온라인 적응은 정상 보정에서 품질과 문맥이 확인된 관측만 사용한다. 갑작스러운
바람, 수동 조작, 실행 결과 불명확, 포화, 프레임 재사용, 참조 변경 구간은 제외한다.
변화율을 제한하고 독립 검증을 거쳐 반영한다. 정보가 부족하면 기본/기존값을 유지하며
학습을 위해 평상시 관측에 임의의 GoTo나 진동을 추가하지 않는다.

### 기록과 재현

세션별 manifest와 append 가능한 이벤트 로그에 프레임·명령·상태 전환·후보·평가를
동일한 ID로 연결한다. 장비 응답 원본, 노출·게인·촬영 시각, 제외 사유를 남겨 이후
느린 복귀가 모터 응답, 관측 지연, 잡음 판정 중 어디에서 발생했는지 구분할 수 있게 한다.

캘리브레이션 영상은 설정한 저장 예산 안에서 작은 완료 가능한 청크로 기록한다.
프레임 메타데이터와 ROI/원본 구분을 함께 저장하고, 별도 분석에 필요한 시험 구간은
우선 보존한다. 전원 차단 시 이미 끝난 청크와 로그를 읽을 수 있어야 한다. 저장 큐는
유한 크기로 하여 제어를 지연시키지 않으며 저장 누락·디스크 부족은 manifest에 남긴다.
재현에 필요한 기록이 빠진 후보는 자동 채택하지 않고 기존값을 유지한다.
대용량 영상과 원본 로그는 데이터 디렉터리에 저장하고 Git에는 넣지 않는다.

### 구현 순서와 회귀 검사

단계별 완료 조건을 충족한 뒤 다음 단계로 진행한다. 문서 작성 자체는 서비스 재시작,
실장 시험, 기존 smooth 통합의 자동 실행을 의미하지 않는다.

| 단계 | 구현 내용 | 완료 조건 |
|---|---|---|
| 1 | 계약·단위·명령 소유권, 세션 조정자와 기록기, 주변 좌표 계획 | 실제 장비 없이 상태 전환·취소·한계 검사 가능 |
| 2 | 기존 펄스 측정 확장, 기본값 기준 시험 | 드라이버별 실행 계약 확인, 응답을 올바른 시각의 관측과 연결 |
| 3 | 칼만 추정기와 기존 필터 비교, 제한된 PID 후보 생성 | 지연·잡음·반전·포화를 포함한 시뮬레이션과 재생 검증 |
| 4 | 실제 비교 시험, 원자적 프로파일 저장, 정상 GoTo 복귀, UI | 사용자 요청 세션에서 완료/취소/대기/실패 모두 검증 |
| 5 | 정상 관측 중 적응과 여러 위치 프로파일 | 기존 성능을 악화시키지 않는 점진적 갱신·복귀 검증 |

조정자, 응답 식별, 상태 추정, 후보 평가를 각각 순수 로직으로 분리하고 기존 서비스가
호출한다. 새 파일을 만든다면 `tracking_autocalibration.py`, `tracking_response.py`,
`tracking_estimator.py`, `tracking_tuning.py` 등을 후보로 삼는다. 이 이름들은 현재
구현 파일이 아니며 기존 모듈과 책임이 겹치면 확장으로 통합한다.

필수 자동 검사는 다음과 같다.

- 좌표: RA 경계·고적위·Alt/Az·시야 회전, aligned 축과 camera 축 구분, 이동 범위 밖
  명령 거부, 원점 복귀 오차, 명령 방향과 접평면 부호 변환.
- 시각: 중복/지연 프레임, 가변 노출·누락 프레임, 노출과 펄스 겹침, 시간 epoch 변경,
  늦은 실행 결과와 부분 실행량. 같은 이동을 두 추정기에서 중복 적용하지 않음.
- 장비 모델: 축 속도 차이·반대 부호·축 결합·백래시·비선형·공유 가이드 속도·포화·
  알려지지 않은 지연. 불충분한 방향은 검증 완료로 표시하지 않음.
- 외란: 순간 바람과 지속 이탈, 수동 이동, 솔빙 오류, 회전·배율 변경, 카메라 노출 변경.
  잘못된 모델 학습 방지와 큰 실제 이탈의 재획득을 함께 검사.
- 수명주기: 모든 상태에서 Stop·새 GoTo·Align, 내부 자식 GoTo의 소유권, 이중 보정
  방지, 연결 소실 후 Push/사용자 의도 유지, 재연결·재시작에서 자동 이동 없음.
- 평가와 저장: 학습/검증 분리, 개선 미확인 시 기존값 유지, 불리한 시험 누락 방지,
  취소 직후 후보 완료, 저장 실패·전원 차단·부모 hash 불일치, 영상 저장 지연.
- UI: 시작 범위와 대기 사유, 후보 채택과 복귀 완료 구분, 정상 GoTo의 위치·시각·화면
  수명주기, 연결 표시와 S/I/M 이동량 출처 표시 회귀.

기존 `test_smooth_tracking*`, `test_tracking_target_integration.py`,
`test_alignment_tracking_flow.py`와 기본 GoTo/Guide 회귀를 함께 실행한다.
구현 변경 후 저장소의 lint·format·type_hints·smoke·unit·관련 UI 검사를 통과해야 한다.
현장 검증은 서로 다른 응답 특성의 장비에서 반복하고, 실제 확인한 장비·방향·속도·
위치 범위만 결과에 명시한다. 시뮬레이터 통과를 모든 장비의 지원 보증으로 사용하지 않는다.

### 근거와 적용 범위

- [PHD2 도구 설명](https://openphdguiding.org/man/Tools.htm)은 영상에서의 별 자동 선택,
  현재 위치 캘리브레이션과 측정 품질 평가를 제공한다. 이 문서의 주변 GoTo 및 PID
  후보 비교 절차는 MFNavis용 설계이며 PHD2가 같은 절차를 제공한다는 뜻은 아니다.
- [PID 자동 튜닝 원리](https://www.mathworks.com/help/slcontrol/ug/how-pid-autotuning-works.html)는
  시험 입력과 측정 응답으로 계수를 구하는 근거다. MFNavis는 펄스·지연·출력 제한을
  포함한 자체 모델과 검증을 사용하며 해당 상용 도구를 실행 의존성으로 요구하지 않는다.
- [조건별 PID 튜닝](https://www.mathworks.com/help/slcontrol/ug/gainscheduledpidautotuner.html)은
  여러 동작 조건의 프로파일을 다루는 참고다. 좁은 주변 측정만으로 전 하늘 응답을
  확인했다는 결론을 내리지 않는다.
- [칼만 필터](https://www.mathworks.com/help/control/ug/kalman-filtering.html)는 모델과
  과정·측정 잡음 공분산을 사용하는 상태 추정의 근거다. 필터 추가만으로 중심 접근이
  빨라지거나 바람을 제거한다고 보증하지 않는다.
- [온라인 추정](https://www.mathworks.com/help/ident/ug/what-is-online-estimation.html)은
  관측 중 장비 모델 갱신의 참고다. 식별 가능한 입력과 관측 품질을 별도로 검증한다.
