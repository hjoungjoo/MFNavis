# 별 검출이 어려운 환경의 상대 추적 시험

2026-10-11. 별이 많이 보이는 초기 평가를 보완해 **적은 별과 낮은 대비**를 중심으로
테스트용 추적 코드를 수정했다. 운영 소스·서비스·장비 설정은 변경하지 않았다.
이 결과는 픽셀 단위 합성 영상의 오프라인 비교이며 실제 구름 속 마운트 보정 성능은 아니다.

## 변경한 테스트용 추적 방식

[새 시험 코드](../../python/scripts/benchmark_weak_star_fallback.py)의 `WeakStarReplay`를
[기존 시험 코드](../../python/scripts/benchmark_visual_fallback.py)의 `RelativeReplay`와 비교한다.
기존 5개 별·전체 영상 재검출 방식은 비교 기준으로 유지했다.

- 기준 별 위치 주변의 작은 영역을 우선 검사한다. 배경을 제거하고 별 모양의
  필터로 희미한 점을 찾으며, 전역 별 목록에서 빠져도 로컬 측정은 가능하다.
- 공간적으로 분산된 별 3개 이상과 일관된 자세 변화가 있으면 승인한다.
  최종 inlier의 분포도 검사한다. 별 1~2개나 일렬로 모인 별은 자세 관측으로 승인하지 않는다.
- 신호 세기뿐 아니라 점의 폭과 주변 경쟁 후보도 검사한다. 가느다란 핫픽셀,
  넓은 구름 밝기 덩어리, 모호한 가까운 점을 거부한다.
- 단일 프레임이 불충분하면 0.4초 안의 최대 3개 프레임을 비중첩 구간으로 합친다.
  이 결과는 프레임 시각의 평균에 해당하는 **지연된 관측**으로 기록한다.
  현재 프레임에서도 같은 위치에 별 3개 이상이 확인되어야 승인하므로 과거 영상의
  잔상만으로 추적을 이어가지 않는다. 큰 이동으로 흐려진 결과도 품질 검사를 통과해야 한다.
- 처음부터 희미한 경우 정착한 3개 프레임을 사용해 기준을 만들고, 각 별을
  최소 2개 입력 프레임에서 확인한다. 영상 기준 확보와 이후 추적 성공은 별도로 집계한다.

현재 실험의 단일 관측 SNR 기준은 5.5, 누적 결과의 현재 프레임 확인은 4.0이다.
이 SNR은 필터·PSF 적합으로 얻은 값이며 아래 표의 픽셀 피크/잡음비와 다르다.
별 분포는 중심을 뺀 좌표의 작은 특잇값 8픽셀 이상, 자세 재투영 RMSE 0.8픽셀
이하를 요구한다. 영상 공백 5초를 넘으면 기존 기준으로 자동 재개하지 않는다.
실험값을 운영 설정에 적용한 것은 아니다.

## 시험 영상과 비교 조건

512×512 영상에 카메라 회전으로 계산한 알려진 별 이동을 넣었다. 별 중심점
정답은 평가기에만 전달하고 추적기는 실제 픽셀만 읽는다. 배경에는 이동하는 넓은
밝기 변화, 독립 가우시안 잡음과 센서 위치에 고정된 핫픽셀을 넣었다.
가까운 경쟁 점, 별 위치의 핫픽셀·넓은 구름 덩어리, 게인·배경 변화는 별도 자동 검사에 포함했다.

- 실제 남은 별 수: 0, 1, 2, 3, 4, 8개.
- 별 피크: 배경 위 8, 15, 25, 60 ADU. 잡음 표준편차는 5 ADU.
- 따라서 픽셀 피크/잡음비는 1.6, 3, 5, 12다.
- 기준 확보 후 시험은 24조건 × 32프레임, 프레임 간격은 0.1초다.
- 희미한 상태의 초기 기준 확보는 15조건 × 10회다.
- 개발 시드 `41011`과 구분한 최종 평가 시드 `20261012`를 사용했다.

정상 기준 확보 후 시험은 처음에 8개 별을 선명하게 본 뒤 검출 조건이 악화되는 상황이다.
처음부터 희미한 경우의 결과는 별도 표에서 확인한다. 실제 구름의 산란·별 모양 변화나
센서의 모든 잡음을 재현한 모델은 아니다.

## 기준 확보 후 추적 결과

각 칸은 **기존 시험 → 수정 시험의 승인 수 / 32프레임**이다.

| 남은 별 수 | 피크 8 ADU | 피크 15 ADU | 피크 25 ADU | 피크 60 ADU |
|---|---:|---:|---:|---:|
| 3개 | 0 → 0 | 0 → 13 | 0 → 32 | 0 → 32 |
| 4개 | 0 → 0 | 0 → 18 | 0 → 32 | 0 → 32 |
| 8개 | 0 → 1 | 13 → 30 | 32 → 32 | 32 → 32 |

별 0~2개 조건은 두 방식 모두 384프레임 전체를 거부했다. 수정 방식의 승인
254건에서 관측 시각 기준 이동량 오차는 중앙값 **0.075픽셀**, p95 **0.246픽셀**,
최대 **0.386픽셀**이었다. 1픽셀 초과 오차 승인은 없었다.
이는 이 합성 시험에서의 결과이며 실제 영상의 오검출 확률을 보증하지 않는다.

누적 영상으로 승인한 것은 6건이다. 별 3개·피크 15에서 3건, 4개·피크 15에서
2건, 8개·피크 8에서 1건이며 모두 관측 시각이 최신 프레임보다 0.1초 이전이다.
피크 8에서 1건이 승인된 것을 지속 추적 가능으로 해석하면 안 된다.
피크 15에서도 별 3~4개 조건의 관측 누락이 많아 보정을 계속 보낼 수 있는 성능은 아니다.

추적 성공 수는 관측을 새로 승인한 횟수다. 누적에 쓰인 과거 프레임을 모두 성공으로
소급 집계하지 않는다. 유효한 관측이 없을 때 직전 좌표를 유지한 것도 성공으로 세지 않는다.
이동량 오차는 관측 시각의 정답과 비교하며, 최신 프레임 시각과의 차이도 JSON에 별도로 기록한다.

## 처음부터 희미한 경우

각 조건을 독립 잡음으로 10회 반복했다. 마지막 두 열은 전체 10회 중 기준 확보
후 첫 새 프레임에서 측정한 횟수와, 새 프레임 3개 안에 한 번 이상 측정한 횟수다.

| 별 수 / 피크 ADU | 기존 기준 확보 | 수정 기준 확보 | 다음 프레임 측정 | 3프레임 내 측정 |
|---|---:|---:|---:|---:|
| 3 / 15 | 0/10 | 9/10 | 1/10 | 7/10 |
| 3 / 25 | 0/10 | 10/10 | 10/10 | 10/10 |
| 4 / 15 | 0/10 | 10/10 | 5/10 | 10/10 |
| 4 / 25 | 0/10 | 10/10 | 10/10 | 10/10 |
| 8 / 15 | 7/10 | 10/10 | 10/10 | 10/10 |
| 8 / 25 | 10/10 | 10/10 | 10/10 | 10/10 |

피크 8 ADU에서는 별 3·4·8개 모두 기준 확보에 실패했다. 별 0·2개 조건도
모든 피크에서 기준을 만들지 않았다. 3프레임 안의 재측정 성공은 장시간 지속
추적이나 실제 보정 성공을 뜻하지 않는다.

기준 영상을 얻는 것만으로 지속 추적이 가능하다고 판단하지 않는다. 기준 확보 뒤
독립적으로 생성한 새 프레임에서 다시 측정되는지도 확인했다. 특히 매우 희미한
조건에서는 이 단계가 실패할 수 있으므로 무조건 보정 명령을 생성하는 정책으로 이어지면 안 된다.

## 처리 시간과 검증 범위

Raspberry Pi 5에서 768개 프레임 전체의 처리 시간은 다음과 같다.

| 시험 방식 | 중앙값 | p95 | 최대 |
|---|---:|---:|---:|
| 기존 전체 검출 + 자세 계산 | 104.03 ms | 152.89 ms | 215.99 ms |
| 수정 ROI + 필요 시 누적 + 자세 계산 | 17.30 ms | 60.03 ms | 146.36 ms |

거부 프레임을 포함한 집계다. 최대값은 0.1초 입력 간격보다 길므로 실제 서비스의
연속 처리율이나 일정한 응답 시간을 이 결과만으로 보장하지 않는다.

시간은 기존 방식의 전체 검출과 자세 계산, 새 방식의 ROI 검사·필요 시 누적·자세
계산을 각각 포함한다. 합성 영상 생성과 파일 저장 시간은 제외했다. 이는 512×512
시험 영상 결과이며 이전 1920×1080 RAW 평가의 시간과 직접 비교하지 않는다.
운영 MFDS 검출 결과를 재사용하는 경로의 실제 지연은 별도로 검증해야 한다.

새 검사와 기존 두 검사 파일을 함께 실행해 **70 passed**를 확인했다.
[검사 코드](../../python/tests/test_weak_star_fallback.py)는 낮은 별 수, 희미한 초기 기준,
핫픽셀·구름 덩어리·잡음의 오승인, 기준 설정 중 이동, 신호 재획득, 오래된 프레임,
Stop, 영상 누적 시각과 버퍼 만료, 게인·배경 변화를 검증한다.

아직 실제 구름 영상에 대한 회복률은 확인하지 못했다. 10월 10일 자료에 연속 영상과
중심점 목록이 없는 제약은 [초기 평가](visual_fallback_benchmark_20261011_ko.md)와 같다.
현재 별 폭 모델도 실험의 PSF 범위이므로 실제 카메라 초점·왜곡·노출 변화에 맞춘 검증이 필요하다.
어두운 영상을 합쳐도 신뢰할 만한 별이 남지 않는 경우는 추적 불가로 남긴다.

## 재현 방법과 결과 위치

저장소 루트에서 다음을 실행한다. 출력 디렉터리는 기존에 없어야 한다.

```bash
PYTHONPATH=python .venv-dev-trixie/bin/python \
  python/scripts/benchmark_weak_star_fallback.py \
  --seed 20261012 --frames 32 --cold-trials 10 \
  --output /tmp/mfnavis-weak-star-replay

PYTHONPATH=python .venv-dev-trixie/bin/python -m pytest -q \
  python/tests/test_weak_star_fallback.py \
  python/tests/test_visual_fallback_benchmark.py \
  python/tests/test_visual_tracking.py
```

최종 결과 폴더는
`/home/mfnavis/MFNavis_data/telemetry/20261011_weak_star_benchmark/holdout_retry/`이다.
`summary.json`에는 조건별 집계와 코드 해시, `frames.jsonl`에는 프레임별 승인·거부
원인, 오차와 시간이 있다. 상위 폴더 `pytest.xml`에 자동 검사 결과를 보관한다.
