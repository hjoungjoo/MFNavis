# Solver CPU·메모리 개선 — 2026-09-17

## 변경 내용

- tetra3의 거리순 해시 후보를 상대 좌표 배열로 재사용한다. 최대 32개 배열을 보관하며 배열 메모리 상한은 총 8MiB다. 후보 조회 순서, uint64 해시, 판정 기준, 시간 제한 및 취소 동작은 유지한다.
- 전처리 실행 모드가 바뀌면 사용이 끝난 누적 영상과 완료 결과를 해제한다. 비동기 누적기의 정리는 실행 중 작업이 끝난 뒤 같은 작업 스레드에서 수행한다.
- MFDS 0.3.2은 전처리 임시 배열을 줄이고 clip 작업 버퍼와 출력 바닥값을 재사용한다. 안전한 설정에서는 evidence 상한 처리를 입력 시 한 번만 수행한다. 반환 영상은 다음 호출에서 변경하지 않으며 reset 시 버퍼를 해제한다.

PiFinder는 `deployment/mfds.lock.json`으로 정식 MFDS 0.3.2의 ARM64/x86_64 패키지와 manifest 해시를 고정한다. 로컬 시험 패키지는 설치 대상이 아니다. 전처리 실행 빈도, 시야각 검색 범위, 검출 임계값은 변경하지 않았다.

## 동일 입력 비교

| 측정 | 기존 | 변경 후 |
|---|---:|---:|
| 성공 사례 11개: 패턴 검색 경과 시간 중앙값 | 20.0ms | 11.8ms |
| 어려운 사례 11개, 동일 2,000회 조회: 경과 시간 중앙값 | 114.8ms | 105.6ms |
| 실제 RAW 22회: 전처리 CPU 시간 중앙값 | 1,492ms | 1,290ms |
| 별도 전처리 프로세스 최대 RSS | 403.8MiB | 381.1MiB |

Raspberry Pi에서 운영 서비스와 함께 실행한 측정이다. 다른 작업과 CPU 주파수의 영향을 받을 수 있으며 일반적인 속도 보장이 아니다. 전처리는 첫 5프레임을 워밍업으로 제외했다. 검색은 기존/수정본 실행 순서를 교대로 바꾸고, 어려운 입력은 동일 조회량 후 취소하여 계산량을 맞췄다.

## 검증

- 검색 후보 조회 순서와 좌표·시야각·매칭 결과·판정 상태 일치.
- 실제 1080×1920 RAW 22회, 합성 36회, 비표준 설정 35회에서 전처리 출력과 진단값 일치.
- 검색, 작업 종료, 누적 이력 해제, 스케줄링, 프레임 짝맞춤 및 복구 경로 회귀 테스트 통과.
- MFDS native 검출기 회귀 7개 통과. 검출 알고리즘과 ABI는 유지한다.

단일 코어의 순간 100% 사용은 여전히 가능하다. 목표는 같은 결과를 얻기 위한 연산량과 불필요한 메모리 보관을 줄이는 것이다. 짧은 적용 확인만으로 장시간 메모리 안정성과 모든 관측 환경의 성공률을 보장하지는 않는다.
