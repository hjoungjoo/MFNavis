# GOTO 완료·지속 보정·수동 정렬의 LCD 기준 통일

## 요구 동작

GOTO의 미세 보정 완료 시 LCD 두 축 오차가 각각 0.05° 이하이고,
이후에도 같은 대상을 지속 보정한다. 사용자가 수동으로 중심을 맞추고
정렬하면 현재 지향점을 정렬 대상 좌표로 다시 정의하고 그 위치를 유지한다.
표시값만 0으로 덮어쓰지 않는다.

## 실기 원인

2026-09-14 21:53:01 SkySafari CM은 성공했지만 입력 RA/Dec
12.833333/2.582778°를 카탈로그·솔빙 좌표로 그대로 사용했다.
LCD 토성 대상은 12.492730/2.438622°였다. 기준축 차이로 생긴
각거리 22.173분각과 LCD의 약 0.4°/0.15° 오차를 수치 재현했다.

추적 대상 전달에도 별도 문제가 있었다. 적용 전 실기 상태에서 서비스의
추적 대상은 12.833333/2.582778°, 저수준 보정기의 대상은
12.815985/2.592506°였다. `set_tracking_target`이 이미 켜진 보정기의
대상을 다시 전송하지 않아 직전 수동 이동 위치를 계속 보정할 수 있었다.

## 변경

- SkySafari 입력을 PiFinder GOTO·카메라 정렬·LCD 대상에 사용할 때
  관측일 기준축에서 카탈로그 기준축으로 변환한다. 카메라 기반 좌표를
  SkySafari에 돌려줄 때는 역변환한다. 행성의 겉보기 보정은 유지하는
  기준축 회전이며, 모든 외부 좌표를 ICRS 별 위치로 간주하는 변환은 아니다.
  Stellarium의 기존 J2000 경로와 INDI 전용/다점 정렬 명령은 유지한다.
- LCD, 도착 판정, 펄스 보정이 같은 축 오차 계산을 사용한다.
  전체 각거리와 두 축 절댓값 중 최댓값이 설정값 이하인지 판정한다.
  현재 완료·추적 설정값은 모두 3분각(0.05°)이다.
- 높은 고도/적위에서 전체 각거리만 작아 보정이 멈추지 않도록
  펄스의 작은 오차 무시 범위도 축 오차에 맞춰 축소한다.
- 미세 보정 완료에는 마지막 펄스 종료 이후의 최근 카메라 솔빙이
  필요하다. 완료 후에는 추적 보정기로 같은 대상을 넘겨 유지한다.
- 정렬 시 적분기가 검증된 카메라 투영으로 정렬 축을 즉시 다시 계산한다.
  촬영 시각과 솔빙 성공 시각은 바꾸지 않는다. 처리 중이던 이전 솔빙도
  현재 target pixel로 다시 계산해 과거 정렬이 되살아나지 않게 한다.
  재생 데이터는 이 실시간 재계산에서 제외한다.
- 정렬 변경 시 좌표 평균을 비운다. 추적 대상 변경은 기존 보정기를 끄고
  새 대상을 다시 전송하며, 정렬값이 공유 좌표와 좌표 서비스에 모두
  게시된 뒤 보정을 재개한다. LCD 정렬과 SkySafari 정렬에 적용한다.
- SkySafari 정렬 대상을 LCD에도 게시한다. 가까운 기존 대상의 이름은
  복사해 유지하되 카탈로그 DB 좌표는 변경하지 않는다.
- LCD 상태는 과거 `Complete`에 고정되지 않는다. 현재 오차에 따라
  Tracking/Adjusting을 표시하고 대기·일시정지·다른 추적 대상도 구분한다.

이 변경은 기존 `mf_coordinate_helper_plan`의 "요청 좌표를 변환하지 않는다"
규칙 중 **SkySafari와 PiFinder 카메라/카탈로그 사이의 경계**를 대체한다.
첫 솔빙 전 IMU 정렬과 마운트 고유 좌표의 정책은 이번 변경 대상이 아니다.

## 실기 적용

2026-09-14 22:24 KST, 마운트 정지와 최근 가이드 펄스 종료를 확인하고
로그·설정·상태를 보존한 뒤 PiFinder 서비스만 재시작했다. 서비스 active,
마운트 connected, 카메라 솔빙 및 새 좌표 게시를 확인했다.
재시작 직후 추적 보정은 `waiting_target`이며, 기존 대상을 자동 복구해
이동시키지 않았다. 사용자의 새 정렬 또는 GOTO부터 새 동작이 시작된다.
이전 방식으로 저장된 정렬값은 사용자가 중심을 맞추고 새로 정렬해야 한다.

보존 자료: `PiFinder_data/captures/analysis/20260914_alignment_hold/`.

## 검증과 실기 범위

관련 테스트 506개 통과, 2개 기존 건너뜀. 변경 코드 Ruff 검사 및
설정에 따른 MyPy 7개 소스 검사와 변경분 공백 검사를 통과했다.

실제 토성 좌표 차이, 정렬 후 LCD 오차 0, SkySafari 역변환, 기존 대상
보정 종료와 새 대상 전송, 좌표 게시 대기, 평균 초기화, 처리 중이던
이전 솔빙 도착, 고고도·고적위 축 오차, 오차 재발 시 보정 재개,
펄스 이후 솔빙을 기다리는 완료 판정, LCD 상태 표시를 회귀 검사한다.

실제 관측 중 새 GOTO 도착 및 수동 중심 정렬은 사용자의 실기 재시험이
필요하다. 측정 잡음이나 기계적 외란이 있는 동안 항상 오차가 한계 안에
있다는 보장은 아니며, 벗어나면 새 솔빙을 통해 계속 보정하는 동작이다.
