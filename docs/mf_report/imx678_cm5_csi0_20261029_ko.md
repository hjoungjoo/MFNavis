# IMX678 컨버터 / CM5 CSI0 적용 (2026-10-29)

사용자가 제공한 MFNavis A0 PWR2-PD 회로(2026-10-04) 기준이다.
MIPI_GPIO0/1은 CM5 GPIO34/35 연결로 사용자 확인을 받았다.

## 수정과 설치

- CSI0 4레인, I2C6 0x1a, 발진기 74.25 MHz 전용 오버레이 추가.
- GPIO34 HIGH 후 150 ms, GPIO35 HIGH 후 5 ms 대기.
- 종료 시 I2C SCL/SDA LOW → GPIO35 LOW → 1 ms → GPIO34 LOW →
  150 ms 방전 대기. 다음 전원 켜기까지 I2C LOW 유지.
- 원본 upstream SHA-256을 유지하고 별도 GPL 패치로 시퀀스를 적용.
  일반 Sony 호환 장치에는 기존 시퀀스 유지.
- DKMS 0.2.0 설치, `--activate-converter`로 부팅 설정 백업 및 전환.
- 카메라 메뉴로 다른 센서에 전환했다 돌아와도 컨버터 설정 보존.

부팅 설정 백업:
`/boot/firmware/config.txt.before-imx678-20261028T153723397070Z`

활성 설정:

```ini
[all]
camera_auto_detect=0
dtoverlay=imx678-mfnavis-cm5-converter
```

## 재부팅 전 검증

- 커널 `6.18.50+rpt-rpi-2712`에서 모듈 및 두 오버레이 빌드 성공.
- `scripts/install_imx678.sh --check` 성공.
- 관련 pytest 81개 통과: 카메라 전환, RAW, 프로파일, 렌즈, API 제어 포함.
- 패치된 실제 C 전원 함수의 정상·실패 경로 9가지 호스트 실행 검증.
- CM5IO/CM4IO용 CM5 DTB에 병합 후 GPIO·클럭·레인·링크·pinctrl 검증.
- 변경 Python Ruff, 설치 스크립트 ShellCheck, diff 공백 검사 통과.
- 기존 generic 오버레이의 dormant fragment 6/7 DTC 경고는 기존과 동일.

재부팅 전 실기 상태는 IMX462 설정, IMX678 모듈 미설치,
`rpicam-hello --list-cameras`: `No cameras available!`이었다.

## 실기 검증

설치 후 재부팅과 실제 촬영 검증까지 통과했다. 원본 출력과 촬영 결과 저장 위치:
`/home/mfnavis/MFNavis_data/imx678-validation/`.

- 센서: `imx678 [3856x2180 12-bit RGGB]`, I2C `10-001a`, CSI0.
- 커널: `detected color sensor`, CSI 링크 891 Mbps/lane.
- MFNavis: `imx678_color` 자동 선택, `SRGGB16` 메모리 컨테이너에서
  4비트 이동해 RAW12 복원. stride 7744바이트의 행 패딩 제거 확인.
- 센서를 3회 열고 닫는 동안 RAW 108프레임 수신, 타임스탬프 증가 확인.
- 3개 사이클 모두 아래 노출·게인 조건에서 제어 응답 확인.
- 512×512 MFNavis 프리뷰 3개 저장, 실내 영상 확인.
- 앱 중지 후 GPIO34/35/38/39 모두 output LOW 확인
  (`gpio-idle.txt`). 아날로그 레일 전압·과도 파형은 측정하지 않았다.
- 테스트 종료 후 `mfnavis.service`를 재시작했고 active 상태 확인.
  RAW 전체 프레임 게시와 컬러 센서 SQM 초기화 로그 확인.
- 커널 로그에서 이번 촬영의 CSI timeout / 전원 시퀀스 오류 없음.

| 요청 노출 | 보고된 노출 | 요청 게인 | 보고된 게인 |
| --- | --- | --- | --- |
| 20,000 µs | 20,000 µs | 1× | 1.000× |
| 100,000 µs | 100,000 µs | 2× | 1.995× |
| 400,000 µs | 400,000 µs | 4× | 3.981× |

첫 사이클 RAW 평균은 각 조건에서 약 505 / 2113 / 3855 ADU로 변화했다.
실내에서 400 ms 조건은 대부분 포화되므로 밝기 응답 확인용이며 선형성
보정 측정이 아니다. 촬영 도구의 JSON에는 사이클별 안정화 후 프레임
메타데이터와 통계가 기록되어 있다.

촬영 검증 도구(앱 중지 후 실행하고 완료 후 서비스 재시작):

```bash
timeout 120s .venv-trixie/bin/python scripts/check_imx678_capture.py \
  --output /home/mfnavis/MFNavis_data/imx678-validation/capture
```

## 제한 및 기존 장치 상태

공식 generic `uncalibrated.json`을 그대로 사용한다. libcamera의
`No lux level found` / `no lux value found` 경고가 반복되며, 이는 해당
튜닝의 lux 알고리즘 부재다. 이번 RAW 촬영과 수동 제어는 성공했지만,
색·광도 및 SQM 보정이 완료되었다는 뜻은 아니다. 튜닝 보정은 별도 작업이다.
야간 별 검출·솔빙은 실내 촬영으로 확인하지 않았다.

IMU I2C 0x28 미응답으로 fake IMU에 전환하는 기존 로그도 확인했다.
카메라 작업 범위 밖이며 IMX678 인식 오류와는 별개다.

배선 교차 확인 자료:
[Raspberry Pi CM5 장치 트리](https://github.com/raspberrypi/linux/blob/rpi-6.12.y/arch/arm64/boot/dts/broadcom/bcm2712-rpi-cm5.dtsi),
[RP1 pinctrl 구현](https://github.com/raspberrypi/linux/blob/rpi-6.12.y/drivers/pinctrl/pinctrl-rp1.c).

## 전체 설치 과정에 통합

사용자의 실기 동작 확인 후 `mfnavis_setup.sh`에도 설치 절차를 통합했다.
Pi 5/CM5 Trixie에서는 옵션 없는 일반 설치로 IMX678 지원을 준비한다.
새 설치의 기본 카메라는 IMX462이며, 이후 메뉴에서 IMX678을 선택하면
CM5의 CSI0 컨버터 설정을 자동 적용하고 재부팅한다. 기본 `keep`은 재설치
시 기존 카메라를 보존한다. `MFNAVIS_CAMERA`는 관리용 선택사항일 뿐이다.

필수 패키지를 libcamera 검사 전에 설치하고, 커널 헤더 메타패키지와
이미 설치된 같은 종류의 커널용 DKMS 빌드를 포함했다. 코드 전용 업데이트는
기존 계약대로 OS 설치·카메라 선택을 하지 않는다.

설치 계획·실패 처리·커널 선택 및 기존 설치/카메라 회귀 테스트 61개 통과.
현재 커널의 실제 모듈 빌드와 `--check`, ShellCheck, Bash 구문 검사,
변경 테스트의 Ruff 검사를 통과했다. 이 단계에서는 새 OS 전체 설치나
현재 장비의 패키지 재설치를 실행하지 않았으며, 설치 결정 로직은 격리된
환경에서 검증했다. 사용법은 [설치 옵션](../mf_dev/setup_ko.md#mfnavis-설치갱신)에 정리했다.

메뉴 기본값 수정 후 관련 테스트 47개를 통과했다. CM5/CM5 Lite 기본값,
일반 Pi 기본값, IMX462 기본 설치 이후 최초 메뉴 선택, IMX462/IMX296/IMX477
전환 후 IMX678 복귀, 중복 선택 시 재부팅 생략, 컨버터 오버레이 누락 시
잘못된 일반 프로파일로 전환하지 않는 동작을 확인했다. 메뉴 콜백에서 실제
부팅 설정 작성 함수까지 연결하고 부팅 파일·재부팅 요청을 검증했으며,
이 단계에서 실제 장비의 센서를 교체하거나 다시 재부팅하지는 않았다.
옵션 없는 새 설치가 `--install`로 지원만 준비한 뒤 `--default imx462`를
호출하는 것도 확인했다. 설치된 권한 실행 스크립트와 같은 독립 실행 방식에서
IMX462 기본 선택 → IMX678 → IMX462 → IMX678 전환도 임시 부팅 파일로 검증했다.
