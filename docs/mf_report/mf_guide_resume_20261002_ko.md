# 렌즈 재보정 후 보정 반복 진단 (2026-10-02)

23:26:41 새 M31 GOTO 이후의 실행 로그를 확인했다. 이 구간은 가이드 펄스가
아니라 sync+GOTO가 반복됐다. OnStep은 GOTO 중 추적을 Off로 보고하며,
도착 후에는 On으로 돌아왔으므로 이동 중 Off만으로 추적 고장을 판단할 수 없다.

코드에서 확인한 별도 결함은 `toggle_guide_correction()`이 같은 목표로
재개할 때에도 최저 오차, 악화 횟수, 소비한 솔빙 시각과 이동 후 관측 경계를
초기화하는 것이다. 솔빙이 간헐적으로 실패하면 보정 악화를 감지하는 세 번의
관측이 계속 초기화되어, 반대 보정이 반복되어도 중단 판단이 늦어진다.

같은 목표의 중단/재개에서는 관측 경계와 수렴 감시 기록을 보존한다. 새로운
목표 또는 새 GOTO에서는 물리 위치가 달라지므로 수렴 기준을 초기화한다.
예측 드리프트는 중단 시 계속 초기화하여 오래된 속도를 재사용하지 않는다.

INDI 표준의 TRACK 모드를 시험했으나 OnStep의 ON_COORD_SET Busy가 도착 후에도
유지되어 기존 완료 판정과 충돌했다. 이 변경은 원복했으며 기존 SLEW 모드를 유지한다.
검증: 관련 테스트 358개 통과, Ruff lint/format 및 git diff --check 통과.
솔빙 중단을 사이에 넣은 악화 관측 테스트에서 동일 프레임을 다시 사용하지
않고 세 번의 악화 관측 후 추가 펄스를 중단함을 확인했다.

이 추가 구간은 앞 구간과 사이에 정지·시각 복구가 있었으며 연속 6분 측정은 아니다.
마지막으로 추적을 끄고 1분간 기록했다. 초기 정지 기준은 30초다.

측정은 앱의 `pointing_coordinate_status.json` 중 독립 `imu` 항목의
`metadata.raw_alt`, `raw_az`, `quat`, 원본 시각을 사용했다.
화면의 혼합 좌표나 평활화된 고도·방위각은 사용하지 않았다.
마운트 값은 직렬 `:GAH`, `:GZH`, `:GX42`, `:GX43`, `:GXF3`, `:GXF4`를
약 0.25초 간격으로 조회했다. 앱이 제공하는 독립 IMU 시각 간격은 약 2초다.
추적 중 보정 GOTO나 앱 가이드 펄스를 이용한 시험은 아니다.

불확실하다. 갱신된 시각과 동일 쿼터니언이 함께 나타났으므로 단순히 오래된

### 해석과 한계

IMU 좌표 표시에서 고도 역방향·고고도 과속과 유사한 현상을 재현했다.
내부 추적 명령이 정지한 뒤에도 고도 출력이 계속 변하기 때문에
IMU 값을 실제 모터 이동의 독립적인 정밀 기준으로 사용할 수 없음이 드러났다.
센서의 자세 융합/재수렴, IMU 처리 경로, 기구의 실제 처짐·미끄러짐 중 어느 것이
이 변화를 만든 것인지는 고정 표적 영상이나 독립 각도계 없이 확정하지 못한다.
각도에 따른 차이는 확인했으나 순차 시험이므로 시간에 따른 드리프트도 함께
섞여 있다. 순수한 고도 의존성을 확정하려면 각도 순서를 바꾼 반복이 필요하다.

이번 결과만으로 방위축 정상 여부를 확정할 수 없다. 방위각 IMU 값에는
YAW 드리프트가 있으며 기대 추적량보다 큰 변화와 부호 불일치가 관측됐다.
마운트 내부 고도 추적은 모든 추적 구간에서 증가 방향이었다.
따라서 이 시험은 모든 고도에서 일관된 내부 방향 반전을 보여주지는 않았다.

이 결과가 이전 실외 카메라 측정의 고고도 과속까지 IMU 오류로 설명한다는 뜻은
아니다. 미라크·M33·히말의 기존 분석 표본은 `source=CAM`이고
표본 시각이 마지막 솔빙 성공 시각과 일치함을 재확인했다.
실외의 실제 시야 이동과 이번 실내 IMU 출력 이상은 별도 증거로 유지한다.

### 시험 중단·복구 및 종료 상태

초기 시도 중 앱과 별도 프로세스의 BNO055 직접 I2C 조회가 겹친 뒤
센서가 CONFIG 모드와 무효 쿼터니언을 보고하여 시험을 자동 중단했다.
앱 프로세스를 짧게 정지한 상태에서 원래 사용하던 IMUPLUS 모드(8)로 복구하고
프로세스를 재개했다. 그 후 전체 각도 시험을 다시 수행했으며 위 표는
복구 후 완료된 구간만 사용했다. 완료된 시험에서는 별도 I2C 조회를 하지 않았다.
자이로·가속도 보정 상태는 각각 3이었다. 원시 자이로·가속도를 함께 측정한
실험은 아니며 칩 펌웨어나 모터 펌웨어를 변경하지 않았다.

종료 시 `:Q`, `:Td`를 실행하고 현지 날짜·시각과 UTC+9를 복구했다.
실내 IMU 좌표 활성화를 위해 추가했던 임시 앱 위치 설정은 기존 `None`으로
돌렸다. INDI 드라이버를 다시 연결한 뒤 CONNECT=On, TRACK_OFF=On,
수동 NS/WE 이동 모두 Off를 확인했다.
