# MFNavis m3.0.1 검증 기록

검증일: 2026-10-17. Raspberry Pi / Trixie 64-bit / Python 3.13.

## 변경 범위

- 새 사용자 GoTo의 안전한 한계 잠금 해제와 요청별 확인 응답.
- 가변 속도 수동 축 근거리 접근, 새 솔빙 확인, 여유 있는 펄스 전환.
- 접근 종료·취소·사용자 수동 조작 시 원래 수동 속도 복원.
- 광학 도착 후 펄스 비수렴의 장기 대기를 제한된 근거리 복구로 전환.
- LCD 상단 상태 아이콘 간격과 웹 INDI Smooth optical tracking 설정 위치.
- m3.0.0 이후 main의 Finder 카메라 IMU GoTo 및 키 입력 후 1초 지연 포함.

첫 전체 실행에서 생성자를 생략한 기존 테스트 대역 5건에 새 수동 접근 상태와
속도 복원 메서드가 없어 실패했다. 대역을 실제 초기 상태에 맞게 갱신했으며,
해당 두 테스트 파일 50개를 다시 통과했다. 운영 코드의 안전 검사를 우회하거나
실패 테스트를 제외하지 않았다. 표의 전체 재검사 결과를 게시 기준으로 사용한다.
UI의 두 건너뜀은 기존 UIAlign의 실시간 솔빙·정렬 순서에 해당하며 새 생략 규칙은 없다.

실행 명령:

```bash
source scripts/activate_dev_trixie.sh
python -m nox --no-venv -s lint format type_hints smoke_tests unit_tests ui_tests
python -m nox --no-venv -s docs
python ../scripts/check_cedar_free.py --repo ..
bash ../scripts/setup_mfds.sh
```

## 재현과 안전 검사

- 실제 서비스·큐·실행기 연결 테스트에서 고정된 오차로 펄스 비수렴을 재현하고,
  큰 이탈을 기다리거나 네이티브 GoTo를 반복하지 않고 근거리 복구함을 확인했다.
- 최초 접근과 도착 후 재접근 모두 솔빙 간격 3·6초, 모터 응답 65·100·120%,
  잔여 오차 4.17·6·14·45′ 조합으로 실제 명령 지속 시간 기반 시뮬레이션을 수행했다.
- 이동 후 새 관측 경계, 구름 중 정지와 속도 복원, 사용자 정지·수동 조작,
  주차·추적 Off·한계 우선권, 10초 재시도 간격과 최대 3회 제한을 확인했다.
- 복구 완료 후 정상 보정·솔빙 소실 중 잔량 보정 재개와 기존 GoTo 완료 정보 보존,
  새 GoTo의 실패 횟수 초기화를 확인했다.

## 실기 확인 범위와 게시

사용자는 수동 근거리 접근의 실제 동작을 확인했다. 도착 후 펄스 실패가 장기
`settling` 대기로 이어지는 운영 로그를 확인해 수정했고, 사용자 승인 후
00:48 KST에 서비스를 재시작하여 정상 실행과 INDI 연결을 확인했다.
재시작 직후 네이티브 추적은 켜져 있었고 새 대상 선택 대기 상태였다.

수정 후 장시간 하늘 추적과 기계적 비수렴 원인, 실제 모터 속도·정지 지연,
새 SD 카드 전체 설치 및 판매용 OS 이미지는 이번 검증 범위가 아니다.
자동 테스트 및 시뮬레이션을 실제 하늘에서의 정밀도 보증으로 취급하지 않는다.

게시 전 동일 소스 커밋의 GitHub Nox 검사 결과를 확인한다. main/release의
실행 링크는 릴리즈 본문과 `release-manifest.json`에 기록한다. 첨부 설치 자료는
커밋된 소스에서 추출하며 `SHA256SUMS`로 무결성을 확인할 수 있다.
개인 Codex 설정 및 이번 릴리즈와 무관한 작업 중 문서는 포함하지 않는다.
