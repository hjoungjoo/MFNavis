# 솔빙 실패 시 별 영상 추적 오프라인 성능 평가

별이 적고 희미한 환경을 대상으로 보완한 코드와 후속 결과는
[약한 별 상대 추적 시험](weak_star_fallback_benchmark_20261011_ko.md)을 따른다.
아래 결과는 초기 5개 별 기준의 비교 자료로 유지한다.

2026-10-11, Raspberry Pi 5 Model B Rev 1.0에서 실행했다. 운영 Python 모듈과
장비 설정은 수정하지 않았으며 마운트·카메라·서비스 제어 명령은 보내지 않았다.
별 대응과 상대 이동 측정의 실현 가능성을 평가한 결과이며 실제 추적 보정의
폐루프 성능이나 정렬 입력부터 솔빙 복귀까지의 운영 통합을 검증한 결과는 아니다.

## 10월 10일 구름 테스트 기록의 재생 가능 범위

베가·데네브·토성의 `runtime.jsonl`을 분석했다. 이 파일에는 상태와 좌표가 있으나
같은 시각의 영상 또는 전체 검출 중심점 목록이 없어 상대 영상 이동을 재계산할 수 없다.
`captures/solver_sessions`의 23개 세션은 10월 2일·6일·7일 기록이며 10월 10일
세션은 없었다. `solver_debug_dumps`도 비어 있었다. 확인한 저장 위치와 세션 목록은
결과 폴더의 `input_inventory.json`에 남겼다.

| 대상 | 기록 시각 KST | 상태 표본 수 | 표본에서 확인한 서로 다른 성공 관측 시각 수 |
|---|---|---:|---:|
| 토성 | 10월 10일 21:58:46–22:02:28 | 370 | 0 |
| 베가 | 10월 10일 22:02:14–22:06:02 | 480 | 45 |
| 데네브 | 10월 10일 22:06:48–22:09:47 | 360 | 63 |

위 수치는 폴링 상태에서 확인한 값이다. 시작 이전의 성공 관측과 중복 시각을
제외했으며, 솔빙 시도 횟수나 성공률을 뜻하지 않는다. 이 기록으로 어제의 구름
상황에서 영상 추적이 얼마나 유지됐을지는 판단할 수 없다.

## 평가 코드와 방법

- 실행기: [benchmark_visual_fallback.py](../../python/scripts/benchmark_visual_fallback.py).
- 검증: [test_visual_fallback_benchmark.py](../../python/tests/test_visual_fallback_benchmark.py).
- 재사용 계산: 기존 `fit_star_pose`, 카메라 기하·왜곡·화면 좌표 변환.
- RAW 검출: 기존 시험용 `detect_test_stars`. 운영 MFDS 검출 성능과는 구분한다.

추적기는 별 중심점, 카메라 기하와 관측 시각만 받는다. 기록된 솔빙 자세와
`matched_centroids`는 추적 입력으로 사용하지 않는다. 솔빙 자세는 추적 계산이 끝난 뒤
비교 점수를 구하는 데만 사용한다. 정답 솔빙 좌표를 바꿔도 추적 출력이 바뀌지 않는
검사를 포함했다.

첫 적합한 정지 프레임을 사용자 정렬로 **모의 설정**하고 로컬 영상 기준을 고정한다.
실제 사용자의 Align 기록을 재생한 것은 아니다. 기준 별을 매 프레임 새로 바꾸지 않으며,
직전 유효 자세는 별의 탐색 위치를 예측할 때만 사용한다. 절대 좌표나 펄스를 게시하지 않는다.
RAW 파일은 해시와 frame ID 대응을 확인하며 역순 프레임은 기준 재설정에도 사용하지 않는다.

시험 조건은 최소 대응 별 5개, 탐색 반경 12픽셀, 재투영 RMSE 한계 1.5픽셀,
별 분포 최소 폭 20픽셀, 최대 유효 영상 공백 10초, 후보 최대 128개다.
이 수치는 이번 실험 조건이며 운영 기본값으로 확정한 값은 아니다.

## 합성 이동과 구름 모의 시험

독립적으로 생성한 카메라 회전과 투영을 정답으로 사용했다. 1920×1080 화면의
48개 별에 0.1픽셀 표준편차의 위치 잡음을 더하고, 일부 별 소실·무작위 가짜 점,
별 0개·2개 구간을 넣었다. 프레임 간격은 0.5초, 난수 seed는 `20261011`이다.
실제 구름 영상의 밝기·형태를 합성한 시험은 아니며, 별 목록이 변하는 상황의 시험이다.

| 항목 | 결과 |
|---|---:|
| 전체 평가 프레임 | 240 |
| 충분한 별이 있는 프레임의 추적 | 208 / 208 |
| 별 0개 또는 2개 프레임의 잘못된 승인 | 0 / 32 |
| 타겟 이동량 오차 중앙값 | 0.0185픽셀 |
| 타겟 이동량 오차 95백분위 | 0.0390픽셀 |
| 타겟 이동량 오차 최대 | 0.0686픽셀 |

이 수치는 알려진 투영에 대한 오차다. 영상 검출은 포함하지 않으며 관측된 구름
오검출 전체에 대한 정확도나 실제 마운트 응답을 보증하지 않는다.

## 10월 6일 RAW 기록 재생

어제의 영상 대신 저장된 데네브 기록 두 개를 보조 평가에 사용했다. 두 세션의
RAW는 1920×1080, uint16이며, 프레임마다 왜곡 보정과 90도 회전, target pixel
좌표 변환을 적용했다. 성공 솔빙도 추적기에는 숨겨서 상대 영상만으로 추적했다.

| 기록 | 저장 RAW | 기준 프레임 | 평가 프레임 | 별 대응 성공 | 솔빙 비교 표본 |
|---|---:|---:|---:|---:|---:|
| 21:38:54 시작, 무보정 shadow 기록 | 11 | 1 | 10 | 10 | 10 |
| 22:10:15 시작, 축별 펄스 응답 기록 | 241 | 3 | 238 | 238 | 232 |

긴 기록은 solver generation 변경 때 기준을 무효화하고 다시 모의 정렬했으므로
3개 구간으로 나뉜 결과다. 241장을 하나의 기준으로 연속 추적한 결과가 아니다.
저장 RAW의 솔빙 실패 2장 중 하나는 모의 기준 설정에 사용됐고, 다른 하나는
추적 평가 대상이었다. 후자는 73개 별 대응으로 추적에 성공했지만 그 프레임의
정답 솔빙이 없으므로 이동량 정확도는 확인할 수 없다.

| 기록 | 솔빙 대비 타겟 픽셀 오차 중앙값 | 95백분위 | 최대 |
|---|---:|---:|---:|
| 짧은 기록 | 0.154 | 0.347 | 0.353 |
| 긴 기록 | 0.383 | 0.684 | 1.525 |

같은 고정 기준점이 현재 영상에 투영되는 위치를 비교했다. 기록된 솔빙 자체의
오차, 광학 모델과 당시 bias 처리의 영향도 포함되므로 위 값은 절대 정답 대비
추적 오차가 아니다. 절대 솔빙 기준이 없는 구간은 이 비교에서 제외했다.

## 처리 시간과 해석

처리 시간은 별 대응·자세 추정, 시험용 RAW 별 검출, 좌표 변환을 구분해 JSON에
기록한다. 디스크 읽기·압축 해제·해시 확인·카메라 노출·큐 전달 지연은 계산 시간에서
제외했다. 정상 실행 중인 장비의 벽시계 측정이며 전용 벤치마크 환경의 보증값은 아니다.

| 평가 | 별 대응·자세 추정 중앙값 / 95백분위 | 시험용 별 검출 중앙값 / 95백분위 | 전체 계산 중앙값 / 95백분위 |
|---|---:|---:|---:|
| 합성 유효 관측 | 21.7 / 51.4 ms | 제외 | 제외 |
| 짧은 RAW 기록 | 34.8 / 60.5 ms | 783.7 / 804.6 ms | 822.9 / 863.8 ms |
| 긴 RAW 기록 | 31.3 / 68.3 ms | 773.5 / 849.1 ms | 809.6 / 880.8 ms |

환경: Python 3.13.5, NumPy 2.2.4, SciPy 1.16.3.

긴 기록의 저장 프레임 간격 중앙값은 약 0.458초다. 전체 RAW를 시험용 검출기로
매번 다시 처리하는 시간은 이보다 길었다. 따라서 운영 통합은 설계대로 **이미 계산한
MFDS 중심점을 재사용하는 경로**부터 검증하는 것이 적절하다. 이번 측정은 MFDS 재사용
경로의 종단 지연을 측정한 것은 아니며 실제 통합 시 프레임 전달과 품질 검사 시간을 더해야 한다.

## 자동 검사와 미검증 범위

새 벤치마크 검사와 기존 `test_visual_tracking.py`를 함께 실행해 **52 passed**를
확인했다. Ruff lint·format과 `git diff --check`도 확인했다. JUnit 결과는
`telemetry/20261011_visual_fallback_benchmark/pytest.xml`에 저장했다.

검사는 누적 이동 보존, 별 부족·장기 공백 거부, 중복·역순 프레임 차단, Stop 후
자동 재개 금지, 파일 해시·프레임 pairing 오류, 정답 솔빙의 추적 입력 유출 방지를 포함한다.
테스트용 상태 관리의 검사이며 운영 GoTo 서비스의 새 동작이 구현됐다는 뜻은 아니다.

아직 확인하지 않은 것은 10월 10일 실제 구름 영상에서의 추적 유지율, 무솔빙 정렬의
운영 이벤트 연동, 첫 solve로 한 번만 타겟을 고정하는 제어 전환, 실측 축 응답을 사용한
펄스 보정 효과다. 다음 구름 시험에서는 정렬 전후부터 복구까지 실패 프레임도 포함한
연속 RAW 또는 전체 검출 중심점, 같은 frame ID의 메타데이터, 정렬·펄스·정지 이벤트를
함께 남겨야 한다. 이번 작업에서는 새 기록이나 장비 시험을 시작하지 않았다.

## 재현 방법

저장소 루트에서 개발 venv를 사용한다. `--output`은 기존에 없는 디렉터리를 지정한다.
실행기는 지정한 결과 디렉터리만 생성하며 기존 입력·운영 설정을 덮어쓰지 않는다.

```bash
PYTHONPATH=python .venv-dev-trixie/bin/python \
  python/scripts/benchmark_visual_fallback.py \
  --synthetic \
  --runtime /home/mfnavis/MFNavis_data/telemetry/20261010_vega_cloud_test/runtime.jsonl \
  --runtime /home/mfnavis/MFNavis_data/telemetry/20261010_deneb_cloud_test/runtime.jsonl \
  --runtime /home/mfnavis/MFNavis_data/telemetry/20261010_saturn_cloud_test/runtime.jsonl \
  --capture /home/mfnavis/MFNavis_data/captures/solver_sessions/f4e12ac19e4845fe8776da642934e660 \
  --capture /home/mfnavis/MFNavis_data/captures/solver_sessions/326898d1829d43c9ab74c02907c20008 \
  --output /tmp/mfnavis-visual-fallback-replay

PYTHONPATH=python .venv-dev-trixie/bin/python -m pytest -q \
  python/tests/test_visual_fallback_benchmark.py python/tests/test_visual_tracking.py
```

최종 결과는 `/home/mfnavis/MFNavis_data/telemetry/20261011_visual_fallback_benchmark/final/`의
`summary.json`, `synthetic.jsonl`, `capture_0.jsonl`, `capture_1.jsonl`이다.
요약에는 입력 로그·사용 모듈·벤치마크 코드의 SHA-256과 실행 환경을 기록했다.
원본 RAW와 프레임별 결과는 저장소에 추가하지 않는다.
