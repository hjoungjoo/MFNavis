## 목표와 현장 조건

따라서 자동 보정 OFF 전후의 관측만으로 물리적 흔들림을 소프트웨어 탓으로 결론 내리지 않는다.
고고도 비교는 사용자가 직접 이동 완료를 확인한 뒤 시작했다.

전처리 실행 간격, 왜곡 k1(−0.11), 품질·연속성 기준, 노출 제어 설정, 최종 허용 오차(3분각)를 변경하지 않았다.
자동 보정 `indi_tracking_guide_enabled`만 시험 중 일시적으로 끄고 수정 적용 후 원래 true로 복구했다.
처음 수집 당시와 복구 후 config.json의 값 차이는 없었다. 자동 노출의 실제 노출 시간은 구간마다 달랐다.

## 2. 별도로 확인한 제어 문제

기존 로그에서 21:51:25, 21:51:50, 21:52:13, 21:52:37, 21:53:00 등에
`No solve anchor within 12s before recovery goto; using pifinder_imu_estimate/medium coordinate`가 기록됐다.
이후 같은 좌표로 Mount SYNC와 복귀 GoTo가 실행됐다. 21:52:37 SYNC의 상태 기록에는
`pointing_source=pifinder_imu_estimate`, `solve_age_seconds=22.9`가 남았다.

이는 ‘12초를 기다렸으므로 새 솔빙이 아닌 추정 좌표도 재정렬 기준으로 허용’하는 실제 실행 경로다.
바람에 의한 흔들림의 원인과 별개로, 재정렬 좌표의 신뢰 근거가 부족해지는 문제로 판단했다.
이 자료만으로 각 복귀 이동이 실제 중심 오차를 얼마나 만들었는지는 확정하지 않는다.

## 3. 구현·적용한 변경

변경 소스: `python/PiFinder/indi_goto_guide_service.py`.

- 자동 복귀 GoTo는 source=solve/quality=high이며 유효한 촬영 timestamp가 있는 관측을 요구한다.
- 관측 시각이 미래이거나 12초보다 오래되면 복귀 SYNC/GoTo를 보내지 않는다. 상태 파일 갱신 시각으로 대체하지 않는다.
- 복귀 솔빙 대기가 12초를 넘겨도 IMU 추정값으로 진행하지 않는다. 자동 보정을 보류하고 새 정상 솔빙이 오면 다시 판단한다.
- 일반 GoTo의 정지 후 솔빙 대기는 기존 12초를 유지한다. 시간 초과 시 추정 좌표로 다음 재정렬·완료 판단을 진행하지 않고 `No fresh plate solve after GoTo`로 종료한다.
- 최근의 정상 정지 후 솔빙이 있으면 기존처럼 즉시 다음 단계 또는 완료로 진행한다.

22:04:23 KST에 PiFinder 서비스를 재시작해 적용했다. 재시작 직전 이동 없음과 자동 보정 OFF를 확인했다.
재시작 후 마운트 연결·기본 추적·솔빙 복구를 확인하고, 22:07:02에 자동 보정을 true로 복구했다.
마운트 컨트롤러/INDI 서버 자체의 재부팅은 수행하지 않았다.

검증:

- GoTo/Guide·mount-control·pointing 관련 테스트 **155개 통과**.
- 오래된/미래/없는 timestamp, IMU 추정 상태에서 대기 시간이 지나도 SYNC/GoTo가 나가지 않는 검사.
- 나중에 정상 솔빙이 도착하면 복귀하는 검사와 정상 정지 후 솔빙의 즉시 완료 검사.
- Ruff 검사·포맷 확인, 대상 모듈 MyPy, diff 공백 검사 통과.
- 실제 고고도 솔빙 복구 및 사용자 요청 토성 GoTo 완료 확인.

이 변경은 작업서 C2/C4의 일부다. **펄스 자체의 노출 구간 검사, 평균 창의 모든 표본 나이 검사,
최초 GoTo 시작 앵커의 전체 정책을 함께 고친 것은 아니다.** 제어 전반의 모든 오래된 좌표 사용을 해결했다고 표현하지 않는다.
솔빙이 없는 대상에서도 12초 뒤 추정 좌표로 계속 재정렬하던 기존 동작은 더 이상 허용하지 않는다.

## 5. 다음 속도 개선 작업의 순서

1. **미세 보정 73초 구간의 연결 계측을 완성한다.** 각 펄스가 실제로 사용한 frame ID, 노출 시작/종료,
   전송·예상/확인 종료 시각, 단일 해와 평균 해를 직접 기록한다. 현재 polling만으로는 늦은 영상 재사용을 확정할 수 없다.
2. **저고도에서 반복 실패하는 중심 경로의 비용을 줄일 방법을 비교한다.** 저고도 OFF 입력에서
   preprocessed Cedar center는 18회 모두 실패했고 시도 시간 중앙값은 301ms,
   SEP center도 18회 모두 실패하며 중앙값 430ms였다. 최종 SEP full은 15회 중 11회 품질 해를 만들었다.
   전체 시야의 잔차·연속성·정렬 지점 정밀도를 유지하는 조건으로 실패 이력 기반 재탐색 예산/순서를 검토한다.
   이 수치는 각 경로 조건부 중앙값이므로 단순 합을 예상 절감 시간으로 단정하지 않는다.
3. **전처리 복구의 전경 대기와 누적 재워밍업을 줄인다.** 새 RAW 처리와 병행할 때 프레임·관측 시각·세대를 보존하고
   CPU 경합을 측정한다. 전처리 실행 간격 변경은 계속 제외한다.
4. **큰 보정과 펄스 보정의 전환 시점을 평가한다.** 이번 6.86분각 진입에서 73초가 걸린 이유를 바탕으로,
   유효 좌표 공급 간격과 펄스의 실제 이동량을 고려할 수 있다. 한 번의 결과로 near threshold나 guide 강도를 새 기본값으로 정하지 않는다.
5. 현재 RAW 미확보 시 bias 적용 일관성 문제와 평균/단일 좌표 판단 차이도 남아 있다.
   연속성 검사를 약화하거나 이동 평균을 무조건 늘리는 방식은 사용하지 않는다.

이번 판정: 보호 수정은 적용 유지, 정상 GoTo 완료 확인. **속도 개선율은 아직 미검증**이며 동일 조건 반복 시험이 필요하다.
사용자 확인과 기록을 바탕으로 현재 토성 관측을 계속할 수 있도록 자동 보정 설정은 원래 상태로 복구했다.
이번 관측 수정은 로컬 소스와 실행 프로세스에 반영했으며 서버 푸시는 수행하지 않았다.
