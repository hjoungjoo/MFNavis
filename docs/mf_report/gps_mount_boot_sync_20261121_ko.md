# 부팅 후 GPS 위치·시간의 마운트 자동 동기화

## 원인

- 마운트 자동 연결은 `sync_on_connect=False`, `preserve_mount_state=True`로
  연결만 수행한다. 일반 GPS `fix`/`time` 수신은 공유 상태만 갱신하므로,
  연결 이후 GPS가 확보되어도 마운트에 위치·시간을 전달할 경로가 없었다.
- 기존 주석에서 언급하는 A5 재동기화 훅은 현재 메인 루프에 없다.
- `SharedStateObj.set_datetime()`은 이전 시각보다 늦은 GPS 시각만 받아들여,
  초기 시각이 미래로 틀어진 경우 큰 역방향 보정을 거부했다.
- INDI 위치·시간 전송 헬퍼의 장치 탐색 및 연결 대기는 시스템 시계를
  사용했다. GPS/chrony가 시계를 뒤로 보정하면 제한 시간이 늘어날 수 있었다.

## 변경

마운트 프로세스가 1초 간격으로 연결, 잠긴 관측 위치와 civil datetime을
확인한다. GPS가 먼저 잡히거나 마운트가 먼저 연결되어도 조건이 갖춰지면
위치·시간을 보낸다. 기본 위치나 시스템 시각만으로 자동 초기화하지 않는다.

전송 성공뿐 아니라 새 `GEOGRAPHIC_COORD`/`TIME_UTC` 응답과 실제 값을
확인한 후 완료로 기록한다. 전송 실패, Alert, 값 불일치, 응답 제한 시간
초과 시 30초 후 최신 값으로 재시도한다. 직접 LX200 경로는 기존 헬퍼의
명령 응답 검증을 사용한다.

다음 조건에서는 다시 동기화한다.

- 연결 세대가 바뀐 경우
- 위도·경도가 0.001도 이상 또는 고도가 100m 이상 바뀐 경우
- 단조 시계 경과를 제외한 civil datetime 보정량이 2초 이상인 경우
- 임시 시각에서 GPS/NTP로 검증된 시각으로 바뀐 경우

GPS 미세 오차나 정상적인 시간 경과만으로는 반복 전송하지 않는다.
이동·정렬·가이드 보정 중에는 동기화를 유예한다. 자동 동기화는 기존
초기 정렬의 unpark/추적 시작 경로를 호출하지 않으며, 직접 LX200 재연결도
정지한 마운트의 추적을 켜지 않는다.

GPS civil datetime은 2초 이상의 역방향 보정도 허용한다. 1초 수준의
역방향 수신 흔들림과 사용자가 지정한 수동 시각은 기존처럼 보호한다.
INDI 헬퍼의 제한 시간은 단조 시계로 계산한다.

## 검증

`test_mountcontrol_indi.py`, `test_state_datetime.py`, `test_sys_utils.py`에
늦은 GPS/연결, 위치 이동, 양방향 시각 보정, 신뢰 상태 변경, 재연결,
전송 및 응답 실패 후 재시도, 이전 응답 배제, 이동 중 유예, 추적 OFF 유지,
시스템 시계 역행 시 제한 시간에 대한 회귀 테스트를 추가했다.

실제 장비의 전원 재부팅과 GPS 이동 수신 검증은 수행하지 않았다.
배포 후에는 `mount_control_status.json`의 `automatic_location_sync_state`
(`waiting_location_time`, `verifying`, `ready`) 및 INDI 위치·UTC 값을 확인한다.
